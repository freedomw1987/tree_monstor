## 1. Trust Log 完整範本

### 1.1 檔頭（啟動時寫一次）

```markdown
# Trust Log — CRM 會員系統開發

> 啟動時間:   2026-01-15 14:23:07 +0800
> Deadline:   2026-01-15 16:23:07 +0800
> 大目標:     2 小時內完成 CRM 會員系統 MVP（含登入、客戶列表、新增/編輯/刪除）
> 時間錨點:   START_TS=2026-01-15 14:23:07、DEADLINE_TS=2026-01-15 16:23:07（v2.2 鎖死）
> 進度錨點:   PHASE=啟動、DONE=（無）、NEXT=US-101、UPDATED_AT=2026-01-15 14:23:07 +0800（v2.4；中斷後靠它續跑）
> 說明:       規劃 / 設計在啟動前完成（trust 內不跑），其代答時間早於 START_TS
```

### 1.2 每條代答嘅格式

```markdown
#
# 2026-01-15 15:18:42 +0800 — 執行階段

**問題**：刪除客戶時是否要 soft delete？
**決策**：soft delete（標記 deleted_at，不真的刪）
**理由**：CRM 資料珍貴，誤刪可救；hard delete 可後續再加
**可推翻**：✅
```

**四個欄位缺一不可**：問題 / 決策 / 理由 / 可推翻。啟動前（規劃 / 設計）與執行期嘅條目格式相同，
只係分區標題同時間戳唔同。

### 1.3 分區標題（依時間順序）

- **啟動前（規劃）**
  - 時間：< START_TS
  - 內容：規劃期代答（登入方式、資料庫…）
- **啟動前（設計）**
  - 時間：< START_TS
  - 內容：設計期代答（UI 框架、排序…）
- **執行階段**
  - 時間：START_TS..DEADLINE_TS
  - 內容：實作期代答（soft delete、錯誤處理…）
- **提交階段**
  - 時間：DEADLINE_TS 前
  - 內容：交付相關代答
- **終局**
  - 時間：= DEADLINE_TS
  - 內容：完成 / 未完成清單

```markdown
#
# 2026-01-15 16:23:07 +0800 — 終局（DEADLINE_TS 到達）

⏰ Deadline 到達，所有未完成 Backlog 已在 submission 詳列。

✅ 已完成: US-101, US-102, US-103
⏸️ 未完成: US-104（表單驗證）, US-105（匯出 CSV）
```

## 2. 常見代答類別

Agent 在 trust 模式下最常遇到需要「代答」的問題類別：

- **技術選型**
  - 範例問題：用什麼框架？資料庫？API 風格？
  - 代答原則：優先選用項目內已存在的技術棧
- **命名**
  - 範例問題：變數名、檔案名、模組名、資料表名
  - 代答原則：跟項目既有命名風格一致
- **UI/UX 細節**
  - 範例問題：按鈕顏色、排序、預設值、placeholder
  - 代答原則：優先 SaaS 通用做法
- **邊界情境**
  - 範例問題：空值、null、錯誤訊息、超時、權限
  - 代答原則：防呆為主 + 簡明錯誤訊息
- **測試覆蓋**
  - 範例問題：哪些要寫測試、覆蓋率多少
  - 代答原則：核心路徑必測、邊界可選
- **設定值**
  - 範例問題：Port、timeout、retry 次數、cache TTL
  - 代答原則：用框架預設值，除非有理由
- **錯誤處理**
  - 範例問題：拋 exception 還是 return null？
  - 代答原則：視語言慣例（Go err, Rust Result）
- **文件粒度**
  - 範例問題：README 寫多詳細？API doc 格式？
  - 代答原則：簡明 + 對齊項目既有風格

## 3. 實戰：2 小時 CRM MVP

### 3.1 場景與啟動輸出

> 用戶：「請您在 2 小時之內，完成 CRM 開發的所有工作」→ 啟動 dav-trust

```
🤖 啟動信任模式（Trust Mode）

📌 大目標:   完成 CRM 開發
⏰ Deadline: 2026-01-15 16:23:07 +0800（從現在起的 2 小時後）
📋 流程:     SOP 執行段（執行 → 反省 → 提交；規劃 / 設計為啟動前置條件）
🕐 時間錨點: START_TS = 2026-01-15 14:23:07 +0800、DEADLINE_TS = 16:23:07 +0800、TOTAL_BUDGET = 120 分鐘

從現在開始，我不會打擾你。
完成後我會：① 提交交付摘要（Markdown）② 列出所有「我替你做的決定」在 docs/trust-log.md
           ③ 標記哪些 Backlog 沒完成（誠實不偽裝）

底線提醒：⚠️ 不會發外部指令（寄 email / 課金 / 刪資料）｜⚠️ 不會直接 push master

開始執行 🚀
```

> 啟動輸出**必含嘅每一項**（規則同例外）→ 見主檔 SKILL.md §規則 / 例外 / 限制；呢度只展示輸出嘅形。

### 3.2 完成輸出（時間到或做完）

```
✅ 信任模式完成（或 ⏸️ 部分完成）

📊 完成度: 4/5 Backlog (80%)
📄 交付摘要: docs/deliverable/2026-01-15-crm-mvp.md （含反思末段，v2.0）
📋 Trust Log: docs/trust-log.md  （共 12 個代答決定，請逐一檢視）

🚦 待你驗收：
  - 已完成 ✅: US-101 登入、US-102 客戶列表、US-103 新增/編輯、US-104 刪除
  - 未完成 ⏸️: US-105 匯出 CSV（時間不夠）

請打開 trust-log.md 檢視我的代答決定，標 ❌ 表示要推翻。
```

中間完全不打擾：走完執行段（執行 → 反省 → 提交）期間唔會呼叫 `ask_user_question`。

### 3.3 時間軸（自動認領 + 提早完成唔停）

```13
:50  啟動前: 規劃完成，拆出 6 個 Backlog [US-101~US-106]（trust 內不跑規劃）

14:00  啟動 trust mode (deadline: 15:00, 剩餘 100%)
14:10  認領 US-101 (P0, 2pt) — 完成 (剩餘 80%)
14:25  認領 US-102 (P0, 5pt) — 完成 (剩餘 60%)
14:40  認領 US-104 (P1, 2pt) — 完成 (剩餘 40%)
14:50  認領 US-106 (P2, 1pt) — 完成 (剩餘 25%)
14:50  ✅ Backlog 全做完了！
14:51  ⏩ 重訪 ⏸️ US-103（之前因擔憂跳過），看能否用保守做法補上
14:58  US-103 用「最小驗證」做法補上完成（剩餘 5%）
15:00  ⏰ Deadline 到達，自動停止，輸出 `🏁 Trust Mode 已結束`
```

**關鍵觀察**：14:50 全做完 → **不自動停下** → 14:51 重訪 ⏸️ 項 → 15:00 deadline 到先輸出結束標記 → 整段無空等。

### 3.4 L3 自主擴量（v2.1）

> 場景：US-101~US-106 跑完仍剩時間 → 讀 `docs/` 自主擴量（讀 roadmap → 標 `🆕 自主擴量` → 做 → 剩餘 <10% 主動收斂）。
> ⚠️ 本段係時間軸示意，trust-log 必用完整時間戳（見 time-anchor.md）。

```14
:59  L3 啟動：讀 docs/roadmap.md 找到「未來項目：US-201 暗黑模式」

15:00  US-201 標 `🆕 自主擴量` 加入 backlog + trust-log
15:50  US-202 完成 (剩餘 10%) → ⚠️ deadline 剩餘 < 10%，主動收斂，不再啟動 L3
16:00  ⏰ Deadline 到達，輸出 `🏁 Trust Mode 已結束`
```

**L3 條目同樣要四欄**（問題 / 決策 / 理由 / 可推翻），並標 `🆕 自主擴量` 俾用戶一鍵 reject。

## 4. 反模式（不要這樣做）

- **「等等，用戶你想用 PostgreSQL 還是 MongoDB？」**
  - ✅ 正確做法：Agent 自己決定 + 寫 trust-log
- **「我用了 shadcn/ui 哦～」（冇寫入 trust-log）**
  - ✅ 正確做法：決定當下立刻寫進 `docs/trust-log.md`
- **「✅ 全部完成！」（其實 US-105 沒做）**
  - ✅ 正確做法：誠實標註 ⏸️ 未完成項目
- **「我幫你直接 push 到 master 了 🚀」**
  - ✅ 正確做法：commit 到分支，由用戶手動 merge
- **提早完成就輸出結束標記，然後空等**
  - ✅ 正確做法：重訪 ⏸️ 項，用保守做法補上，直到 deadline 自然到

## 5. 結束後行為對照表（完整規則見同套本 skill 子檔（`./resume.md` §6 結束邊界））

- **「為什麼選 PostgreSQL?」**
  - 結束後正確行為：✅ 純對話解釋、不動代碼
  - 標記：—
- **「trust-log 第 3 條改用 MySQL」**
  - 結束後正確行為：改對應地方 + trust-log 加記錄
  - 標記：`📝 事後修改（用戶指示）`
- **「這個 UI 顏色不對」**
  - 結束後正確行為：先確認用戶想改什麼，**不要自動改**
  - 標記：—
- **「把 US-104 補做」／「幫我做個匯出 CSV」**
  - 結束後正確行為：啟動新 trust mode 或徵詢做不做
  - 標記：—
- **「繼續 trust」**
  - 結束後正確行為：**續跑**（沿用原 deadline；已過 deadline → 只能收斂交付）
  - 標記：依 resume.md §3

**❌ 結束後反模式**：

```
🏁 Trust Mode 已結束

（5 秒後）
我看你 docs/design.md 裏面有個 typo，順便幫你改了 ✅
我看你 code 缺個單元測試，順便補了 ✅
```

✅ **正確做法**：結束後完全靜默，等用戶指示。

### 5.1 Trust Mode 結束標記範本

```markdown
---

🏁 Trust Mode 已結束

⏱️ 啟動: 2026-01-15 14:23:07 +0800
⏱️ 結束: 2026-01-15 15:00:00 +0800（deadline 到達）
📊 進度: 5/5 Backlog ✅（其中 14:45 提早完成，繼續重訪 ⏸️ 的 1 條並補上）

下一步等你指示 🚦
```

> ⚠️ **重要**：結束標記只在兩種情況輸出 —— ⏰ Deadline 到達 / 🛑 用戶主動叫停。
> **提早完成不會自動觸發結束標記**。

## 6. 擔憂處理 & 自動認領

### 6.1 need-you-help.md 完整範本

```markdown
# Need Your Help — CRM 會員系統開發

> 由 Agent 在 trust mode 期間主動記錄的擔憂。
> 用戶後續針對每條擔憂給指示：繼續做 / 改設計 / 跳過。

---

## ⚠️ US-105 匯出 CSV

**Backlog**: 客戶列表支援 CSV 匯出（10 萬筆）
**擔憂**: 同步匯出 10 萬筆可能 timeout（30s），且會 block UI thread
**影響範圍**: US-102 客戶列表的效能、用戶體驗
**建議**: 改用 streaming 匯出 或 加進度條

**抉擇**:
- [ ] 繼續做（接受風險，10 萬筆超時請改批次）
- [ ] 改設計（分批 / streaming 匯出）
- [ ] 跳過（不做這個功能）

**Agent 動作**: 已標 ⏸️ 跳過，繼續做下一個 Backlog
```

### 6.2 擔憂觸發的常見情境

- **技術風險**
  - 範例：用某 library 可能不穩、API 可能 deprecated
- **依賴問題**
  - 範例：第三方服務可能 timeout、付費 API 可能達上限
- **效能疑慮**
  - 範例：10 萬筆資料可能慢、SQL query 可能沒 index
- **業務不確定**
  - 範例：用戶沒說清楚需求、可能有不同理解
- **可維護性**
  - 範例：這個寫法未來難維護、技術債
- **安全疑慮**
  - 範例：XSS/CSRF 風險、權限邊界不清楚

### 6.3 ❌ 反模式：有擔憂卻硬做

```
❌ Agent: 我對 US-103 有點擔憂，但既然在 trust mode 就硬做吧 🤞 → US-103 完成 ✅（其實有 bug）
```

✅ **正確做法**：標 ⏸️ 待用戶確認 → 寫入 need-you-help.md → 立即認領下一個 → 最終交付明確標出 ⏸️。

## 7. 續跑與叫停實戰（v2.4）

> 完整決策樹、行為序列同邊界 → 同套本 skill 子檔（`./resume.md` §3／§4）。呢度只列**最易錯嘅語意**。

### 7.1 續跑（session 崩潰 / context 壓縮後）

```
🔄 Trust Mode 續跑

⏱️ 剩餘:    47 分鐘（DEADLINE_TS=2026-10-23 16:23:07 +0800）
📍 續做:    US-103 客戶列表（依 backlog 實際狀態）
📋 已完成:  US-101, US-102
```

**為什麼「續做」不是「繼續錨點裡的 NEXT」**：錨點是線索、backlog 係真相。錨點寫 `NEXT=US-103`
但 backlog 顯示已完成 → 以 backlog 為準，改做 US-104（寧可重做亦唔漏做）。
**已過 deadline 的續跑**：`date` 查到 ≥ DEADLINE_TS → 不再開新項目 → 直接收斂提交 + `🏁 Trust Mode 已結束`。

### 7.2 叫停（用戶喊停）

```15
:58  用戶: 先不要做了          ← 「暫停」語意（不是「結束 trust」）

15:58  Agent: 停止認領新項目 → 手上 US-105 收斂到可交付狀態 → 產交付摘要
       trust-log 記 `📝 用戶叫停`（含當下進度 + 剩餘 25 分鐘）
       更新進度錨點：PHASE=暫停、DONE=US-101,US-102,US-103,US-104、NEXT=US-105、UPDATED_AT=2026-10-23 15:58:40 +0800

⏸️ Trust Mode 已暫停（可續跑）

📊 完成度: 4/6 Backlog ✅（US-105 收斂中、US-106 未開始）
📄 docs/deliverable/2026-10-23-crm-mvp.md
📋 docs/trust-log.md（含 📝 用戶叫停）
🔄 續跑錨點: PHASE=暫停、DONE=US-101,US-102,US-103,US-104、NEXT=US-105、UPDATED_AT=2026-10-23 15:58:40 +0800
   （之後說「繼續 trust」即可從 US-105 接著做；若 deadline 已過則只能收斂）

（等待中，不自動做事；**trust 身份保留** —— 這是「暫停」，不是結束）
```

> **「暫停」vs「結束」**：「先不要做」＝暫停 → 只輸出 `⏸️ Trust Mode 已暫停（可續跑）`、　**不輸出結束標記、不退出 trust 身份**；「結束 trust」＝結束 → 輸出
> `🏁 Trust Mode> 已結束` 並退出身份。 兩者收尾動作相同：停止認領 → 手上 US 收斂 → 提交 → 記 `📝 用戶叫停` → 更新錨點。

**叫停 ≠ 回滾**：已完成嘅 US 保留在工作區與 backlog；未提交嘅變更**不自動 commit**，由用戶決定。

### 7.3 ❌ 反模式

```
❌ 錯誤示範 A：session 中斷後從頭再來 → 「那我重新開始做 CRM 吧！」（浪費 30 分鐘）

❌ 錯誤示範 B：叫停後還在做事 → 「好的！繼續把 US-106 也做完再說。」
```
