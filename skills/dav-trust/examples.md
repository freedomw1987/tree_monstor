## 1. Trust Log 完整範本

### 1.1 啟動時的開頭

```markdown
# Trust Log — CRM 會員系統開發

> 啟動時間: 2026-01-15 14:00
> Deadline:   2026-01-15 16:00
> 大目標:     2 小時內完成 CRM 會員系統 MVP（含登入、客戶列表、新增/編輯/刪除）

---

## 2026-01-15 14:05 — 規劃階段

**問題**：用戶沒指定登入方式（Email 密碼？OAuth？Magic Link？）
**決策**：用 Email + Password（傳統帳密）
**理由**：BaaS 預設支援、最常見、不需第三方依賴
**可推翻**：✅

**問題**：用戶沒指定資料庫
**決策**：PostgreSQL
**理由**：CRM 結構化資料多，關聯式資料庫最合適
**可推翻**：✅

---

## 2026-01-15 14:25 — 設計階段

**問題**：UI 框架選擇
**決策**：Tailwind CSS + shadcn/ui
**理由**：Tree monstor 項目已有 Tailwind 設定，shadcn 可直接 copy
**可推翻**：✅

**問題**：客戶列表預設排序
**決策**：依建立時間新到舊
**理由**：SaaS 通用預設
**可推翻**：✅

---

## 2026-01-15 15:30 — 執行階段

**問題**：刪除客戶時是否要 soft delete？
**決策**：soft delete（標記 deleted_at，不真的刪）
**理由**：CRM 資料珍貴，誤刪可救；hard delete 可後續再加
**可推翻**：✅

---

## 2026-01-15 15:55 — 提交階段

**問題**：HTML 交付摘要要用什麼風格？
**決策**：跟 docs/deliverable/ 既有模板一致
**理由**：保持一致性
**可推翻**：❌（屬於 dav-submitter 既有規範）

---

## 2026-01-15 16:00 — 終局

⏰ Deadline 到達，所有未完成 Backlog 已在 submission 詳列。

✅ 已完成: US-101, US-102, US-103
⏸️ 未完成: US-104（表單驗證）, US-105（匯出 CSV）
```

## 2. 常見代答類別

Agent 在 trust 模式下，最常遇到需要「代答」的問題類別：

| 類別 | 範例問題 | 代答原則 |
|------|---------|---------|
| **技術選型** | 用什麼框架？資料庫？API 風格？ | 優先選用項目內已存在的技術棧 |
| **命名** | 變數名、檔案名、模組名、資料表名 | 跟項目既有命名風格一致 |
| **UI/UX 細節** | 按鈕顏色、排序、預設值、placeholder | 優先 SaaS 通用做法 |
| **邊界情境** | 空值、null、錯誤訊息、超時、權限 | 防呆為主 + 簡明錯誤訊息 |
| **測試覆蓋** | 哪些要寫測試、覆蓋率多少 | 核心路徑必測、邊界可選 |
| **設定值** | Port、timeout、retry 次數、cache TTL | 用框架預設值，除非有理由 |
| **錯誤處理** | 拋 exception 還是 return null？ | 視語言慣例（Go err, Rust Result） |
| **文件粒度** | README 寫多詳細？API doc 格式？ | 簡明 + 對齊項目既有風格 |

## 3. 實戰範例：2 小時 CRM MVP

### 3.1 場景

> 用戶：「請您在 2 小時之內，完成 CRM 開發的所有工作」
> → 啟動 dav-trust

### 3.2 Agent 啟動時的對話輸出

```
🤖 啟動信任模式（Trust Mode）

📌 大目標:   完成 CRM 開發
⏰ Deadline: 2 小時後（16:00）
📋 流程:     SOP 5 階段（規劃 → 設計 → 執行 → 反省 → 提交）

從現在開始，我不會打擾你。
完成後我會：
  1. 提交交付摘要（Markdown + HTML）
  2. 列出所有「我替你做的決定」在 docs/trust-log.md
  3. 標記哪些 Backlog 沒完成（誠實不偽裝）

底線提醒：
  ⚠️ 不會發外部指令（寄 email / 課金 / 刪資料）
  ⚠️ 不會直接 push master

開始執行 🚀
```

### 3.3 中間完全不打擾

Agent 走完整流程，不呼叫 `ask_user_question`。

### 3.4 完成的對話輸出（時間到或做完）

```
✅ 信任模式完成（或 ⏸️ 部分完成）

📊 完成度: 4/5 Backlog (80%)
📄 交付摘要: docs/deliverable/2026-01-15-crm-mvp.md
🌐 HTML 版:  docs/deliverable/2026-01-15-crm-mvp.html
📋 Trust Log: docs/trust-log.md  （共 12 個代答決定，請逐一檢視）

🚦 待你驗收：
  - 已完成 ✅: US-101 登入、US-102 客戶列表、US-103 新增/編輯、US-104 刪除
  - 未完成 ⏸️: US-105 匯出 CSV（時間不夠）

請打開 trust-log.md 檢視我的代答決定，標 ❌ 表示要推翻。
```

## 5. 反模式（不要這樣做）

### ❌ 不要在 trust mode 中問問題

```markdown
# 錯誤示範
🤖 等等，用戶你想用 PostgreSQL 還是 MongoDB？
```

✅ **正確做法**：Agent 自己決定 + 寫 trust-log。

### ❌ 不要省略 trust-log

```markdown
# 錯誤示範
Agent: 我用了 shadcn/ui 哦～（沒寫進 trust-log）
```

✅ **正確做法**：決定當下立刻寫進 `docs/trust-log.md`。

### ❌ 不要偽造完成

```markdown
# 錯誤示範
✅ 全部完成！  （其實 US-105 沒做）
```

✅ **正確做法**：誠實標註 ⏸️ 未完成項目。

### ❌ 不要超出底線

```markdown
# 錯誤示範
Agent: 我幫你直接 push 到 master 了 🚀
```

✅ **正確做法**：commit 到分支，由用戶手動 merge。

## 6. 結束後行為對照表（對應 §9.3）

> 這個對照表用於 trust mode 結束後，Agent 收到用戶訊息時該怎樣回應。

### 6.1 用戶追問技術問題

| 用戶說 | 結束前（trust） | 結束後（普通對話） |
|--------|---------------|-----------------|
| 「為什麼選 PostgreSQL?」 | 不用問，決策已寫 trust-log | ✅ 純對話解釋、不動代碼 |
| 「這個函數怎麼用？」 | — | ✅ 純對話、不動代碼 |
| 「shadcn/ui 是什麼？」 | — | ✅ 純對話解釋 |

### 6.2 用戶要求修改

| 用戶說 | 結束後正確行為 | 標記 |
|--------|-------------|------|
| 「trust-log 第 3 條改用 MySQL」 | 改對應地方 + trust-log 加記錄 | `📝 事後修改（用戶指示）` |
| 「這個 UI 顏色不對」 | 先確認用戶想改什麼，**不要自動改** | — |
| 「把 US-104 補做」 | 啟動新 trust mode 或徵詢做不做 | — |

### 6.3 用戶要加新任務

| 用戶說 | 結束後正確行為 |
|--------|-------------|
| 「幫我做個匯出 CSV 功能」 | 「要啟動新 trust mode 嗎？給個 deadline。」 |
| 「再跑 30 分鐘 trust mode 做 X」 | 重新進入 trust mode |
| 「順便修一下這個 bug」 | 確認要不要立即做，不要自動延伸 |

### 6.4 ❌ 結束後反模式

```markdown
# 錯誤示範：結束後還在自動做事
🏁 Trust Mode 已結束
（5 秒後）
我看你 docs/design.md 裏面有個 typo，順便幫你改了 ✅
我看你 code 缺個單元測試，順便補了 ✅
我發現 trust-log 第 2 條可以更好，順便優化了 ✅
```

✅ **正確做法**：結束後完全靜默，等用戶指示。

```markdown
# 正確示範
🏁 Trust Mode 已結束

📊 完成度: 5/5 (100%)
📄 docs/deliverable/2026-01-15-crm.md
🌐 docs/deliverable/2026-01-15-crm.html
📋 docs/trust-log.md (共 12 條代答決定，請檢視)

驗收後告訴我要：
- 接受（沒問題）
- 推翻某些決策（請給編號）
- 加新任務（可啟動新 trust mode）

（等待中，不自動做事）
```

### 6.5 Trust Mode 結束標記範本

```markdown
---

🏁 Trust Mode 已結束

⏱️ 啟動: 2026-01-15 14:00
⏱️ 結束: 2026-01-15 15:00（deadline 到達）
📊 進度: 5/5 Backlog ✅（其中 14:45 提早完成，繼續重訪 ⏸️ 的 1 條並補上）
📋 Trust Log: 12 條代答決定

下一步等你指示 🚦
```

> ⚠️ **重要**：結束標記只在兩種情況輸出（見 §9.1）：
> - ⏰ Deadline 到達
> - 🛑 用戶主動叫停
>
> **提早完成不會自動觸發結束標記**。Agent 會重訪 ⏸️ 跳過的、看能否用保守做法補上，直到 deadline 自然到。

## 7. 擔憂處理 & 自動認領（對應 §5.5）

### 7.1 need-you-help.md 完整範本

```markdown
# Need Your Help — CRM 會員系統開發

> 由 Agent 在 trust mode 期間主動記錄的擔憂。
> 用戶後續針對每條擔憂給指示：繼續做 / 改設計 / 跳過。

---

## ⚠️ US-105 匯出 CSV

**Backlog**: 客戶列表支援 CSV 匯出（10 萬筆）
**擔憂**: 同步匯出 10 萬筆可能 timeout（30s），且會 block UI thread
**影響範圍**: US-102 客戶列表的效能、用戶體驗
**建議**: 改用 streaming 匯出 或 加進度條

**抉擇**:
- [ ] 繼續做（接受風險，10 萬筆超時請改批次）
- [ ] 改設計（分批 / streaming 匯出）
- [ ] 跳過（不做這個功能）

**Agent 動作**: 已標 ⏸️ 跳過，繼續做下一個 Backlog

---

## ⚠️ US-103 表單驗證

**Backlog**: 客戶新增/編輯表單加 zod schema 驗證
**擔憂**: 第三方驗證庫 zod v3 與現有 TypeScript 5.x 相容性未知
**影響範圍**: 表單提交流程
**建議**: 用原生 TypeScript 寫簡單驗證（避免依賴）

**抉擇**:
- [ ] 繼續做（試試看 zod，不行再換）
- [ ] 改設計（用原生 TS 寫）
- [ ] 跳過（不做表單驗證）

**Agent 動作**: 已標 ⏸️ 跳過，繼續做下一個 Backlog
```

### 7.2 自動認領時間軸範例（包含提早完成仍繼續）

```
14:00  啟動 trust mode (deadline: 15:00, 剩餘 100%)
14:00  規劃: 拆出 6 個 Backlog [US-101~US-106]
14:10  認領 US-101 (P0, 2pt) — 完成 (剩餘 80%)
14:25  認領 US-102 (P0, 5pt) — 完成 (剩餘 60%)
14:40  認領 US-104 (P1, 2pt) — 完成 (剩餘 40%)
14:50  認領 US-106 (P2, 1pt) — 完成 (剩餘 25%)
14:50  ✅ Backlog 全做完了！
14:51  ⏩ 重訪 ⏸️ US-103（之前因擔憂跳過），看能否用保守做法補上
14:58  US-103 用「最小驗證」做法補上完成（剩餘 5%）
15:00  ⏰ Deadline 到達，自動停止，輸出 `🏁 Trust Mode 已結束`

最終交付:
- ✅ US-101, US-102, US-103, US-104, US-106 (5/6 提早完成 + 重訪 ⏸️ 補上)
- ⏸️ US-105 (P2, 5pt, 在 14:55 範圍縮小時標「不在此次範圍」)
- 📋 need-you-help.md 列出 US-103 擔憂（已被保守做法補上，可全選或取消）
```

**關鍵觀察**：
- 14:50 Backlog 全做完 → **不自動停下**
- 14:51 重訪 ⏸️ US-103，用「最小驗證」保守做法補上
- 15:00 deadline 到才輸出結束標記
- 整段期間沒有任何「空等」時間

### 7.3 擔憂觸發的常見情境

| 情境 | 範例 |
|------|------|
| **技術風險** | 用某 library 可能不穩、API 可能 deprecated |
| **依賴問題** | 第三方服務可能 timeout、付費 API 可能達上限 |
| **效能疑慮** | 10 萬筆資料可能慢、SQL query 可能沒 index |
| **業務不確定** | 用戶沒說清楚需求、可能有不同理解 |
| **可維護性** | 這個寫法未來難維護、技術債 |
| **安全疑慮** | XSS/CSRF 風險、權限邊界不清楚 |

### 7.4 ❌ 錯誤示範：有擔憂卻硬做

```markdown
# 錯誤示範
Agent 內心: 我對 US-103 有點擔憂，但既然在 trust mode 就硬做吧 🤞
Agent: US-103 完成 ✅ （但其實有 bug、用戶之後才發現）

# 結果：用戶驗收時才發現問題，要返工
```

✅ **正確做法**：

```markdown
Agent 內心: 我對 US-103 有擔憂，應該跳過並記錄
Agent: 
  - 標 US-103 為 ⏸️ 待用戶確認
  - 寫入 need-you-help.md
  - 立即認領 US-104
  - 在最終交付明確標出 ⏸️ US-103 等待用戶指示

# 結果：用戶及時知道問題，避免後續返工
```

### 7.5 ❌ 錯誤示範：提早完成就停下

```markdown
# 錯誤示範：舊規則（已推翻）

15:00  Agent: 啊，因為我以為提早完成就要停下來...

# 結果：浪費了 15 分鐘
```

✅ **正確做法**（新規則）：

```markdown
14:45  Agent: 5/5 Backlog 都完成了！但 deadline 還有 15 分鐘
14:46  Agent: 重訪 ⏸️ US-105（之前因擔憂跳過），看能否用保守做法補上

15:00  Agent: Deadline 到，輸出 `🏁 Trust Mode 已結束`
         6/6 Backlog ✅
```
