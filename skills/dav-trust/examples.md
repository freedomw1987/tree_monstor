## 1. Trust Log 完整範本

### 1.1 啟動時的開頭

```markdown
# Trust Log — CRM 會員系統開發

> 啟動時間: 2026-01-15 14:00
> Deadline:   2026-01-15 16:00
> 大目標:     2 小時內完成 CRM 會員系統 MVP（含登入、客戶列表、新增/編輯/刪除）

---

## 2026-01-15 14:05 — 規劃階段

**問題**：用戶沒指定登入方式（Email 密碼？OAuth？Magic Link？）
**決策**：用 Email + Password（傳統帳密）
**理由**：BaaS 預設支援、最常見、不需第三方依賴
**可推翻**：✅

**問題**：用戶沒指定資料庫
**決策**：PostgreSQL
**理由**：CRM 結構化資料多，關聯式資料庫最合適
**可推翻**：✅

---

## 2026-01-15 14:25 — 設計階段

**問題**：UI 框架選擇
**決策**：Tailwind CSS + shadcn/ui
**理由**：Tree monstor 項目已有 Tailwind 設定，shadcn 可直接 copy
**可推翻**：✅

**問題**：客戶列表預設排序
**決策**：依建立時間新到舊
**理由**：SaaS 通用預設
**可推翻**：✅

---

## 2026-01-15 15:30 — 執行階段

**問題**：刪除客戶時是否要 soft delete？
**決策**：soft delete（標記 deleted_at，不真的刪）
**理由**：CRM 資料珍貴，誤刪可救；hard delete 可後續再加
**可推翻**：✅

---

## 2026-01-15 15:55 — 提交階段

**問題**：HTML 交付摘要要用什麼風格？
**決策**：跟 docs/deliverable/ 既有模板一致
**理由**：保持一致性
**可推翻**：❌（屬於 dav-submitter 既有規範）

---

## 2026-01-15 16:00 — 終局

⏰ Deadline 到達，所有未完成 Backlog 已在 submission 詳列。

✅ 已完成: US-101, US-102, US-103
⏸️ 未完成: US-104（表單驗證）, US-105（匯出 CSV）
```

## 2. 常見代答類別

Agent 在 trust 模式下，最常遇到需要「代答」的問題類別：

| 類別 | 範例問題 | 代答原則 |
|------|---------|---------|
| **技術選型** | 用什麼框架？資料庫？API 風格？ | 優先選用項目內已存在的技術棧 |
| **命名** | 變數名、檔案名、模組名、資料表名 | 跟項目既有命名風格一致 |
| **UI/UX 細節** | 按鈕顏色、排序、預設值、placeholder | 優先 SaaS 通用做法 |
| **邊界情境** | 空值、null、錯誤訊息、超時、權限 | 防呆為主 + 簡明錯誤訊息 |
| **測試覆蓋** | 哪些要寫測試、覆蓋率多少 | 核心路徑必測、邊界可選 |
| **設定值** | Port、timeout、retry 次數、cache TTL | 用框架預設值，除非有理由 |
| **錯誤處理** | 拋 exception 還是 return null？ | 視語言慣例（Go err, Rust Result） |
| **文件粒度** | README 寫多詳細？API doc 格式？ | 簡明 + 對齊項目既有風格 |

## 3. 實戰範例：2 小時 CRM MVP

### 3.1 場景

> 用戶：「請您在 2 小時之內，完成 CRM 開發的所有工作」
> → 啟動 dav-trust

### 3.2 Agent 啟動時的對話輸出

```
🤖 啟動信任模式（Trust Mode）

📌 大目標:   完成 CRM 開發
⏰ Deadline: 2 小時後（16:00）
📋 流程:     SOP 5 階段（規劃 → 設計 → 執行 → 反省 → 提交）

從現在開始，我不會打擾你。
完成後我會：
  1. 提交交付摘要（Markdown + HTML）
  2. 列出所有「我替你做的決定」在 docs/trust-log.md
  3. 標記哪些 Backlog 沒完成（誠實不偽裝）

底線提醒：
  ⚠️ 不會發外部指令（寄 email / 課金 / 刪資料）
  ⚠️ 不會直接 push master

開始執行 🚀
```

### 3.3 中間完全不打擾

Agent 走完整流程，不呼叫 `ask_user_question`。

### 3.4 完成的對話輸出（時間到或做完）

```
✅ 信任模式完成（或 ⏸️ 部分完成）

📊 完成度: 4/5 Backlog (80%)
📄 交付摘要: docs/deliverable/2026-01-15-crm-mvp.md
🌐 HTML 版:  docs/deliverable/2026-01-15-crm-mvp.html
📋 Trust Log: docs/trust-log.md  （共 12 個代答決定，請逐一檢視）

🚦 待你驗收：
  - 已完成 ✅: US-101 登入、US-102 客戶列表、US-103 新增/編輯、US-104 刪除
  - 未完成 ⏸️: US-105 匯出 CSV（時間不夠）

請打開 trust-log.md 檢視我的代答決定，標 ❌ 表示要推翻。
```

## 5. 反模式（不要這樣做）

### ❌ 不要在 trust mode 中問問題

```markdown
# 錯誤示範
🤖 等等，用戶你想用 PostgreSQL 還是 MongoDB？
```

✅ **正確做法**：Agent 自己決定 + 寫 trust-log。

### ❌ 不要省略 trust-log

```markdown
# 錯誤示範
Agent: 我用了 shadcn/ui 哦～（沒寫進 trust-log）
```

✅ **正確做法**：決定當下立刻寫進 `docs/trust-log.md`。

### ❌ 不要偽造完成

```markdown
# 錯誤示範
✅ 全部完成！  （其實 US-105 沒做）
```

✅ **正確做法**：誠實標註 ⏸️ 未完成項目。

### ❌ 不要超出底線

```markdown
# 錯誤示範
Agent: 我幫你直接 push 到 master 了 🚀
```

✅ **正確做法**：commit 到分支，由用戶手動 merge。
