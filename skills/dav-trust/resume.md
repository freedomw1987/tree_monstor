# Dav Trust — Resume（續跑 ＋ 叫停 ＋ 結束邊界）

> 本檔為 dav-trust 子檔。引用：`SKILL.md` §規則「中斷後續跑」+「用戶叫停」+「退出 trust 後不再自動做事」
> 時間紀律（4 個 checkpoint + T5 / 絕對時間戳 / 跨午夜 / 時區 / 已過 deadline 邊角）→ 同套本 skill 子檔（`./time-anchor.md`）
> 主檔只保留規則列與指標；續跑決策樹、checkpoint 契約、叫停行為序列、結束邊界都在本檔。

## §1 為什麼需要

trust 是**長時程**任務，最容易壞掉的不是做錯，而是**中途中斷**：

- **session 中斷 / 崩潰** — 症狀：對話消失、process 死掉；沒機制時的後果：不知道 deadline 還剩多少 → 要嘛超時、要嘛白做
- **context 壓縮** — 症狀：前文被摘要；沒機制時的後果：忘記 START_TS / DEADLINE_TS / 已完成到哪 → 從頭再來一遍
- **使用者叫停** — 症狀：用戶中途喊停；沒機制時的後果：不知道「停下」要做什麼 → 半成品留在工作區、無交付摘要

**核心設計**：把 trust 的狀態**外化到檔案**（trust-log 檔頭 = checkpoint），中斷後不需要「記得」，只需要「讀得到」。

## §2 checkpoint 契約（trust-log 檔頭必含）

trust 啟動時（Step 1），`docs/trust-log.md` 檔頭**必須**寫死以下欄位（缺一不可續跑）：

- **`START_TS` / `DEADLINE_TS`** — 意義：時間錨點（不可變，除非用戶明示改 deadline）；更新時機：啟動時鎖死
- **`PHASE`** — 意義：目前階段（啟動 / 執行 / 反省 / 提交 / 終局 / 暫停）；更新時機：階段切換時
- **`DONE`** — 意義：已完成的 US 清單；更新時機：每完成一個 US
- **`NEXT`** — 意義：下一個要做的 US；更新時機：每完成一個 US
- **`UPDATED_AT`** — 意義：本錨點最後更新時間；更新時機：每次更新

> **寫入位置**：trust-log **檔頭**（不是內文）—— 續跑時第一件事就是讀檔頭，不該先讀全文。
> **更新時不額外跑 `date`**：沿用最近一次 checkpoint 已查到的時間戳（T2 已查時間），避免節奏被打亂（時錨點節奏見 time-anchor.md §2）。
> 檔頭範本（可直接複製）→ 同套本 skill 樣例檔（`./examples/trust-log-formats.md`）。

## §3 續跑程序（重開 session 後的第一步）

### 3.0 觸發條件（誰可以啟動續跑）

- **用戶明示「繼續 trust」** → ✅ 續跑（沿用原 `DEADLINE_TS`）
- **同一 session 內 context 壓縮後自我恢復** → ✅ 續跑
- **新 session、沒有用戶指示** → ❌ **不得自動開工**（主檔「退出後不再自動做事、必須等用戶指示」）

> **「繼續 trust」＝續跑，不是新 trust**：續跑沿用原 `DEADLINE_TS`（已過 → 只能收斂交付）；若用戶要「再做新工作」→ 必須給**新 deadline**，走**新 trust**（Step 1
> 重新鎖錨點）。⚠️ **續跑不是「繼續做」——是先重建狀態**，順序錯了就會重做或漏做。

### 3.1 決策樹

```
讀 docs/trust-log.md 檔頭
├─ 檔案不存在 / 無時間錨點（無 START_TS + DEADLINE_TS）→ 視為「未曾啟動」→ 不續跑 → 普通對話模式，等用戶重新發起 trust
├─ 有時間錨點、無進度錨點（老版本 trust / 崩潰前最後一次寫入沒成功）
│    → 用 backlog 實際狀態重建錨點（PHASE=執行、DONE=backlog 已完成清單、NEXT=第一個未完成 US）
│    → 回到本節的時間判斷分支（date 查現在時間 → 已過 deadline / 剩餘不足 → §3.3 收斂；否則 → §3.2 對齊續做）
└─ 有完整錨點 → date 查現在時間
     ├─ 現在 ≥ DEADLINE_TS → 【已過 deadline】→ §3.3 收斂
     ├─ 剩餘 < 10% → 【收斂】→ §3.3（不認領新 US）
     ├─ 剩餘 < 一個 US 的預估時間 → 【收斂】→ §3.3（不做新 US）
     └─ 剩餘 ≥ 10% 且夠一個 US → §3.2 對齊 + 續做
```

> **10% 的分母** = `TOTAL_BUDGET_EPOCH` = DEADLINE − START（與 time-anchor.md §2 一致）。
> 續跑時的 10% 門檻**比主檔嚴**：主檔是「不再啟動新 **L3 項目**」，續跑是「**不認領新 US**」（刻意收緊 —— 續跑時剩餘時間已不可靠，宁可收斂也不要開工開到一半）。

### 3.2 對齊（先對齊，再動手）

- **1** — 動作：讀 backlog 的**實際狀態**（`docs/backlog.md`）；為什麼：backlog 是單一真相來源，錨點只是線索
- **2** — 動作：與 `進度錨點.DONE / NEXT` 比對，**不一致時以 backlog 為準**，並更新錨點；為什麼：兩者可能不一致（崩潰前最後一次寫錨點沒成功），寧可重做也不漏做；漏做 = 交付物缺一塊
- **3** — 動作：重算剩餘時間（`date` + epoch 差）；為什麼：剩餘是決定「做什麼 / 收斂」的唯一依據
- **4** — 動作：在對話輸出續跑公告（見 §3.4）；為什麼：讓用戶一眼看出「從哪續、還剩多久」

**續跑第一個 US 的選擇**：取 backlog 中優先級最高的未完成 US（不是錨點的 NEXT）——錨點可能過期，backlog 不會。

### 3.3 續跑時「已過 deadline / 剩餘不足」的收斂

- **已過 DEADLINE_TS** — 動作：不做任何新工作 → 立刻走同套 `dav-reviewer` skill 提交（誠實標 ⏸️ 未完成）→ 輸出 `🏁 Trust Mode 已結束`
- **剩餘 < 10%** — 動作：不認領新 US → 只做「收斂型」工作（補測試 / 補文件 / 產交付摘要）→ 提交 → 結束
- **剩餘 < 一個 US 的預估時間** — 動作：同上：不做新 US，改收斂（§3.1 的子條件）。**估計來源**：backlog 的 US 沒有時間欄位 → 以「剩餘 < 30 分鐘」當保守替代門檻（無可信估計時只用 10% +
30 分鐘兩道門檻）

> **收斂 ≠ 放棄**：未完成項目保留在 backlog（標 ⏸️ / todo），可由用戶日後「繼續 trust」重啟。

### 3.4 續跑公告格式（對話輸出）

```
🔄 Trust Mode 續跑

⏱️ 剩餘:    47 分鐘（DEADLINE_TS=2026-10-23 16:23:07 +0800）
📍 續做:    US-103 客戶列表（依 backlog 實際狀態）
📋 已完成:  US-101, US-102
🔀 已修正:  1 處不一致（錨點 NEXT=US-102 → backlog 實際 US-103）
```

**這不是「打擾用戶」** —— 它是狀態公告，不含任何需要用戶回覆的問題。

## §4 叫停（用戶主動喊停）

### 4.1 觸發

用戶任何訊息含下列任一語意 → **立即停止**（優先於其他所有規則，含三段接力）：

- **停止**（例子：「停」「先不要做」「stop」「pause」）— 性質：**暫停**：保留錨點與進度；**不輸出結束標記**、**不退出 trust 身份**（隨時可續跑）
- **結束**（例子：「結束 trust」「不用做了」「cancel」）— 性質：**結束**：保留錨點與進度；輸出 `🏁 Trust Mode 已結束`、**退出 trust 身份**（不再續跑，除非用戶日後說「繼續 trust」）

> 兩者的**收尾動作相同**（停止認領 → 手上 US 收斂 → 提交 → 記 `📝 用戶叫停` → 更新錨點），差別只在**是否輸出結束標記與是否退出 trust 身份**。

### 4.2 行為序列（依序，不可跳）

1. **立刻停止認領新項目** —— 不啟動 L1 / L2 / L3，不開始下一個 US
2. **手上進行中的 US 收斂到可交付狀態** —— 能合理時間內完成就完成；否則標 ⏸️ 未完成（不留半成品）
3. **走同套 `dav-reviewer` skill 產交付摘要** —— 誠實標示 ⏸️ 未完成項目（不偽裝完成）
4. **trust-log 記一條事件**：`📝 用戶叫停`（含時間戳 + 當下進度 + 剩餘時間）
5. **更新進度錨點**（`PHASE=終局`、「暫停」時則 `PHASE=暫停`；`DONE` / `NEXT` = 實際狀態）—— 供日後續跑
6. **對話輸出結束訊息**：「結束」語意 → `🏁 Trust Mode 已結束`（格式見 examples.md）+ 完成度 + 待續跑錨點；「暫停」語意 → 只輸出「⏸️ Trust Mode 已暫停（可續跑）」+ 完成度 +
待續跑錨點，**不輸出結束標記**
7. **「結束」時才退出 trust 身份** → 普通對話模式（不自動做事，等用戶指示）；「暫停」則保持待續跑狀態

### 4.3 邊界（叫停 ≠ 其他）

- **不自動回滾** — 不做 `git reset` / 不刪已完成的產物（除非用戶明確要求）
- **不自動 commit / push** — 未提交的變更留在工作區，等用戶指示
- **不撤銷底線規則的保護** — 叫停不會讓先前的外部指令 / 不可逆操作變成可做
- **不當成「任務失敗」** — 叫停是**使用者決定**，不是違規 → 不寫「假裝通過」類檢舉
- **不用戶回覆也能收尾** — 叫停後 Agent 自己走完 §4.2 的 7 步，不需要再問用戶

## §5 續跑 / 叫停 vs 三段接力與 deadline

- **三段接力（L1→L2→L3）** — 觸發：還有時間、還有活；被叫停 / 過 deadline **立即中止**
- **續跑** — 觸發：session 中斷 / context 壓縮；恢復後**回到三段接力**（L1 優先）
- **叫停** — 觸發：用戶喊停；中止一切、收斂交付、保留錨點
- **deadline** — 觸發：時間到；硬上限；續跑時若已過 → 直接收斂

**殘留風險**：`DEADLINE_TS` 是絕對時間，續跑時必須重新 `date` 查（不可信任上次寫的剩餘時間）。

## §6 結束邊界（核心新規範）

- **Deadline 到達** — 觸發：時間到；Agent 動作：用同套 `dav-reviewer` skill 提交 + `🏁 Trust Mode 已結束`
- **用戶主動結束** — 觸發：「結束 trust」「cancel」「不用做了」；Agent 動作：同上（提交 + `🏁 Trust Mode 已結束` + 退出身份）
- **用戶暫停** — 觸發：「先不要做」「停一下」「pause」；Agent 動作：提交 + `⏸️ Trust Mode 已暫停（可續跑）`；**不輸出結束標記、不退出身份**（見 §4）
- **Backlog 全做完** — 觸發：N/A；Agent 動作：**不結束**；依主檔 §Step 4 走 L1 → L2 → L3 三段接力
- **L3 擴量跑完 `docs/` 預先規劃** — 觸發：停下來等 deadline；Agent 動作：不再啟動新 L3 項目
- **deadline 剩餘 < 10%** — 觸發：主動收斂、標 ⏸️；Agent 動作：不再啟動新 L3 項目

**結束後**：✅ 純對話回應、解釋、推翻舊決策；✅ 等用戶指示才做事；❌ 不可自主延伸（反省、加 Bug、改進）；❌ 不可自動讀 trust-log（除非被問）。
