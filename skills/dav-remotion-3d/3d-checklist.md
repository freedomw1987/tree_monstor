# 3D Checklist — 強度、鏡頭、實作、坑

> 對應 workflow Step 4。呢份係「加 3D」嘅決策同實作細節。

## 3D 強度三檔（先揀檔位，唔好一開始就上真 three.js）

- **L1 平面＋視差**：多層 SVG／DOM 平面，唔同 z 位置，用透視變換 + `perspective`
  - 成本：幾乎零；效果：有深度感但係平面；用喺：標題、卡片、logo reveal
- **L2 CSS 3D**：透視 + 旋轉／位移變換（真 3D 變換，但無 mesh）
  - 成本：低；效果：立體 tilt、翻轉；用喺：文字、面板、裝置 mockup
- **L3 真 three.js**：mesh／光照／陰影／相機
  - 成本：中高；效果：真 3D 空間、景深、反射；用喺：粒子、隧道、3D 場景

**三檔整體強度**（產品簡介片常用）
- 輕：只有 1–2 段係真 3D，其餘 2.5D → 渲染 3–6 分鐘（600 幀）
- 中（常用）：4–6 段有 3D 成分 → 渲染 8–15 分鐘
- 重：全部場景都係 3D 場景，連文案都浮喺 3D 空間 → 20 分鐘以上，文字清晰度差

**判斷準則**
- 想要「厚薄感」→ L1／L2 夠，唔好開 WebGL
- 想要「鏡頭入到場景裏面」→ 必須 L3
- 想要「文字立體」→ L2 就夠（3D 文字要字型檔案，成本高、清晰度差、字型管理麻煩）

**規律**：3D 負責「記憶點」，平面負責「講清楚」。每段 3D 之間插一段平面；產品介面一定要有清晰平面時間（觀眾要睇清功能）。

## 鏡頭語言（一条片最多用兩種）

- 推近 dolly in：深度變化 ≤6 單位／2.5 秒 → 聚焦、強調
- 拉遠 dolly out：反向 → 收束完結
- 環繞 orbit：角度 ≤8°／約 3 秒 → 展示立體感
- 穿越 fly-through：穿過 logo／隧道，fov 由 50 拉到 65 → 「進入產品世界」，最有記憶點
- 抬升 crane：上升 → 揭示全貌
- 視差 parallax：多層深度平面 → 層次、深度
- 俯衝 dive：加速 → 緊迫

## 實作規則

- **單一 canvas**：全片一個 WebGL canvas；場景切換 = 同一 scene graph 切換可見性。多 canvas 會撞 context 上限、慢、記憶體翻倍
- **frame 驅動**：動畫值、相機、亂數全部由當前幀推導；唔可以用真實時鐘
- **seeded 亂數**：每個場景一個固定 seed；預先算好位置存入 props 最穩陣
- **雙面材質**：相機朝 +z 睇時，單面平面會被背面剔除 → 成個 3D 靜靜地唔見咗
- **文字 DOM 疊層**：3D 內不畫字；介面截圖要清晰可讀，唔好當背景糊
- **DOM 對齊 3D**：用相機投影把 3D 座標轉螢幕座標，唔好手調數值
- **材質共享**：卡片／面板共享一份材質；介面截圖共用一張貼圖
- **陰影一次性**：接觸陰影用「只計一次」模式；唔用累積陰影（每幀重算，慢一個數量級）
- **反射用假**：鏡像平面 + 漸變遮罩；唔用光線追蹤反射
- **後處理克制**：泛光／景深只喺高潮段開；每個 pass 都係成本
- **像素比鎖 1**：渲染像素比固定，唔好跟裝置 DPR，否則輸出尺寸唔一致

## 效能預算（產品簡介片，600 幀 @1080p）

- 每幀渲染 ≤1.0 秒；3D 段 ≤1.5 秒；整片 ≤15 分鐘
- Draw call ≤300；粒子 ≤20,000（用 instancing）；面板 ≤30
- 每場景 mesh ≤5、貼圖 ≤3
- 陰影貼圖 512–1024 夠用
- 連機無 GPU 嘅 CI：用軟件光柵模式（慢但穩），或者用雲端 GPU

## 常見坑（10 條）

1. 多個 canvas → context 爆、慢到離譜 → 全片一個
2. 用真實時鐘 → 每幀唔同、第二次 render 唔一致 → 全部改 frame 驅動
3. 用 `Math.random()` → 粒子每次位置唔同 → seeded PRNG
4. 累積陰影／即時反射 → 渲染慢 10 倍 → 一次性陰影 + 假反射
5. 3D 入面畫文字 → 字型 fallback、唔 crisp、冇字幕 → DOM 疊層
6. 單面平面 → 3D 成個唔見咗 → 雙面材質
7. 物理燈光／依賴網絡環境貼圖 → 跨機器結果唔同 → 固定燈光參數、避免網絡資源
8. 開咗 GPU 模式但 CI 機無 GPU → 慢或失敗 → CI 用軟件光柵
9. 陰影貼圖開太細 → 又慢又無謂 → 512–1024 夠
10. 鏡頭郁太快 → 觀眾睇唔切 → 推近 ≤6 單位／2.5 秒；穿越鏡頭加運動模糊

## 唔好加 3D 嘅時候

- 片嘅重點係「講清楚功能」而唔係「炫」→ 用平面 + 清楚的 UI 展示
- 3D 佔比超過一半 → 觀眾記得個效果但唔記得係咩產品
- 冇 GPU 預算（成個 pipeline 要喺 CI 跑幾十次）→ 降到 2.5D
- 品牌本身唔係 3D 風格 → 2.5D 視差已經夠有质感
