# 3D Checklist — 強度檔位、實作規則、坑

> 對應 workflow Step 4。動效揀選（46 個清單）→ 見子檔 [`ad.md`](./ad.md)；呢份係「點實作」。

## 3D 強度三檔（先揀檔位，唔好一開始就上真 three.js）

- **L1 平面＋視差**：多層 SVG／DOM 平面唔同 z，用透視變換 —— 成本幾乎零；標題、卡片、logo reveal
- **L2 CSS 3D**：透視 + 旋轉／位移（真 3D 變換，無 mesh）—— 成本低；立體 tilt、翻轉、裝置 mockup
- **L3 真 three.js**：mesh／光照／陰影／相機 —— 成本中高；粒子、隧道、3D 場景、景深
- **整體強度**：輕 = 1–2 段真 3D（3–6 分鐘／600 幀）｜中（常用）= 4–6 段有 3D（8–15 分鐘）｜
  重 = 全部 3D（20 分鐘＋，文字清晰度差）
- **判斷**：要「厚薄感」→ L1／L2 夠（唔好開 WebGL）；要「鏡頭入到場景裏面」→ L3；要「文字立體」→ L2
- **紀律**：3D 負責記憶點、平面負責講清楚；3D 之間插平面；產品介面一定要有清晰平面時間

## 實作規則

- **單一 canvas**：全片一個 WebGL canvas；場景切換 = 同一 scene graph 切可見性（多 canvas 撞 context 上限）
- **frame 驅動**：動畫值、相機、亂數全由當前幀推導；唔可以用真實時鐘
- **seeded 亂數**：每場景一個固定 seed；預先算好位置存入 props 最穩陣
- **雙面材質**：相機朝 +z 睇，單面平面會被背面剔除 → 成個 3D 靜靜地唔見咗
- **文字 DOM 疊層**：3D 內不畫字；介面截圖要清晰可讀，唔好當背景糊
- **DOM 對齊 3D**：用相機投影把 3D 座標轉螢幕座標，唔好手調數值
- **材質共享**：卡片／面板共享一份材質；介面截圖共用一張貼圖
- **陰影一次性**：接觸陰影「只計一次」；唔用累積陰影（每幀重算，慢一個數量級）
- **反射用假**：鏡像平面 + 漸變遮罩；後處理（泛光／景深）只喺高潮段開
- **像素比鎖 1**：渲染像素比固定，唔跟裝置 DPR，否則輸出尺寸唔一致

## 效能預算（600 幀 @1080p）

- 每幀 ≤1.0 秒（3D 段 ≤1.5 秒）；整片 ≤15 分鐘
- Draw call ≤300；粒子 ≤20,000（用 instancing）；面板 ≤30；每場景 mesh ≤5、貼圖 ≤3
- 陰影貼圖 512–1024 夠用；CI 無 GPU → 軟件光柵或雲端 GPU

## 常見坑（8 條）

1. 多個 canvas → context 爆、慢到離譜 → 全片一個
2. 用真實時鐘 → 第二次 render 唔一致 → 全部改 frame 驅動
3. 用 `Math.random()` → 粒子每次位置唔同 → seeded PRNG
4. 累積陰影／即時反射 → 渲染慢 10 倍 → 一次性陰影 + 假反射
5. 3D 入面畫文字 → 字型 fallback、唔 crisp、冇字幕 → DOM 疊層
6. 單面平面 → 3D 成個唔見咗 → 雙面材質
7. 物理燈光／網絡貼圖 → 跨機器結果唔同 → 固定燈光參數、避免網絡資源
8. 鏡頭郁太快 → 觀眾睇唔切 → 推近 ≤6 單位／2.5 秒

## 唔好加 3D 嘅時候

- 重點係「講清楚功能」而唔係「炫」→ 平面 + 清楚 UI 展示
- 3D 佔比超過一半 → 觀眾記得效果但唔記得產品
- 冇 GPU 預算（pipeline 要喺 CI 跑幾十次）→ 降到 2.5D
