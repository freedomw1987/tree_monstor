# 實例：SOW Details 拆解

> ⚠️ 本檔係**通用化示例**（假設客戶「示例酒店」），唔係任何真實合約內容 —— 用嚟示範寫法，唔可以直接交畀客。
> 對應 skill：`dav-think-sow`

## 場景

示例酒店想喺大堂 kiosk 同官網提供中英雙語數字人禮賓服務，背後接一個知識庫 AI Agent 平台，全部 on-premise 部署。

## Item 1 — 數字人互動應用（產品功能型）

- **Description**：
  - 互動流程控制與數字人動作控制
  - 跨裝置互動：PC、平板、手機
  - 內建 ASR／TTS 串流請求
  - 知識庫與 AI Agent 調用
- **數量**：授權 5 台裝置；含 1 個基本角色、10 組基本動作、1 條基本聲線
- **常見漏**：裝置數冇寫 → 客戶以為可以裝多過 5 台

## Item 2 — AI Agent 平台（平台模組型）

- **Description**：
  - **A. 知識庫管理**
    - 多源資料接入 — 支援文字、網頁及外部檔案系統三類資料集，並可進行向量化與檢索。
    - 文件內容擷取 — 自動抽取文字、表格及圖片內容。
    - 引用與來源連結 — 擷取被引用段落之圖片，並附原始來源連結（PDF／HTML）。
  - **B. Agent 管理**
    - 多 Agent 設定 — 支援多個 Agent 各自設定參數與排程。
    - 多模型對話 — 於同一對話流程中切換不同模型。
    - 檔案上傳與多語言對話 — 支援上傳檔案及以多種語言進行對話。
  - **C. 工作流編排**
    - 依意圖配置流程 — 按對話意圖路由至預先設定的工作流程。
    - AI 與互動元件 — 提供對話、資料集查詢、問題分類、文本擷取、選擇及表單元件。
    - 工具與控制邏輯 — 支援文字拼接、指定回覆、文件解析、HTTP 請求、條件判斷、變數更新及程式執行。
  - **D. 分析報表**
    - 對話紀錄 — 提供對話紀錄、訊息總數及正負評數。
    - 滿意度與時長指標 — 呈現滿意度趨勢及平均對話時長。
- **常見漏**：每個模組淨寫「支援 X」而冇功能類別列舉 → 交付時無從驗收

## Item 3 — 部署與配置（部署配置型）

- **Description**：
  - 部署數字人相關服務
  - 資料庫：MongoDB（工作流管理）、PgVector（知識庫 RAG 向量化）
  - 初始化：回答語言跟用戶語言；文件引用維持原文語言
- **常見漏**：冇講明邊個出機器同 GPU（要寫入 Assumption）

## Item 4 — 擬真數字人客製化（客製化型）

- **Description**：真人實拍影片錄製；AI 驅動動作、表情、口型訓練；聲線複製訓練
- **交付物**：1 個擬真角色、10 段動作錄製、1 個聲線
- **常見漏**：素材由邊度嚟、肖像與聲線授權邊個簽

## Item 5 — 數據增強服務（數據服務型）

- **Description**：
  - 索引：文件分塊與向量化
  - Prompt 工程：按意圖與模型定制 prompt 及測試
  - 意圖 chatbot 工作流與問答分類設計
- **數量**：涵蓋知識庫內 100 份文件（含圖片）
- **常見漏**：文件數係咪上限、超出點計 → 寫入 Assumption

## Item 6 — 評估與 QA 優化（評估優化型）

- **Description**：
  - 人工評分與答案修正（off-topic／irrelevant／過長／過短）
  - Agent Judge 對目標模型評分與修正
  - 每輪產出準確率指標與 RAG 品質報告
  - 題庫與評估集更新並優化 RAG
- **交付物**：評估報告（含統計）＋ 100 組問答評估集
- **常見漏**：冇寫準確率門檻、每輪幾長、報告格式

## Item 7 — 數字人平台授權（自家產品授權型 · Item A）

- **Description**：
  - 本項為軟件授權，涵蓋以下授權範圍
  - **A. 授權範圍**
    - 授權模組 — 數字人互動應用、AI Agent 平台、分析報表
    - 授權對象與角色 — 系統管理員與前台服務人員
  - **B. 授權數量與年期**
    - 授權數量 — 5 台裝置，10 個並發使用者
    - 授權年期 — 1 年，自驗收日起計算
    - 升級與續約 — 首年內含同版本升級；續約另行報價
- **數量**：授權上限 5 台裝置
- **費用**：授權費用於報價表以獨立 License 行項列示（本項不列金額）
- **常見漏**：冇寫授權年期、冇寫升級政策 → 報價行項無法對齊

## Item 8 — 數字人平台部署與調試（自家產品授權型 · Item B）

- **Description**：
  - 本項為安裝部署、參數調校與驗收交接服務
  - **A. 部署**
    - 環境安裝 — 於客戶指定伺服器安裝數字人與 Agent 服務
    - 服務與資料庫初始化 — 初始化 MongoDB、PgVector 及工作流基礎設定
  - **B. 調試與驗收**
    - 情境測試與參數調校 — 依大堂與官網兩種情境測試並調校回覆參數
    - 驗收與交接 — 執行驗收測試並完成操作交接
- **交付物**：部署紀錄、調校報告、驗收報告
- **工作量**：10 mandays
- **常見漏**：冇獨立成 Item（混入授權 Item）→ 報價無法分開列 License 同 Service

## Assumption（三類示範）

- **環境與資源**：全部 on-premise 部署，環境與機器由客戶提供；LLM／embedding／ASR／TTS 模型由客戶提供算力部署
- **範圍與計算基準**：數據增強與評估服務本次合共 30 mandays；超出部分另收費
- **商業假設**：平台授權 1 年，續約另議；授權與部署調試分別對應報價表獨立行項
- **未列明事項**：任何未於本文件列明之服務均不包含於本次交付範圍（Any services not specified above are excluded.）

## 好嘅寫法 vs 壞嘅寫法

- 壞：「支援豐富嘅 AI 對話能力，提升用戶體驗。」
- 好：「Agent 管理：多 Agent 設定、多模型對話、預訓練資料集查詢、檔案上傳、多語言對話、排程任務。」

## 口語 vs 書面語（寫入 SOW 內文時）

> 禁用字眼對照表見 `reference.md` §8；以下只示範最易漏嘅兩種。

- 壞（口語）：「整咗個 AI 客服，客人傾嘅時候會自動答問題。」
- 好（書面語）：「建置 AI 客服模組，於對話過程中自動回覆使用者提問，支援知識庫檢索與工單轉派。」
- 壞（口語）：「呢個模組唔包括數據遷移。」
- 好（書面語）：「本模組不包含數據遷移。」

## 分塊寫法示範（平台模組型 Item）

> 對應 Excel `SOW Details`／`SOW Details CN`：欄位 `#`｜`Item`｜`Description`｜`Mandays`；
> `Description` 用 `A.`／`B.`／`C.`／`D.` 分塊 ＋ 「功能名 — 說明」短句；**徹底刪除 `Module` 欄**；`Mandays` 留空。

- 壞（逐行列舉，讀起嚟冇範疇層級）：「多源資料接入。文件內容擷取。引用與來源連結。多 Agent 設定。」
- 好（分塊 ＋ 標題式短句）：
  - `A. 知識庫管理` → `- 多源資料接入 — 支援文字、網頁及外部檔案系統三類資料集。`
  - `B. Agent 管理` → `- 多 Agent 設定 — 支援多個 Agent 各自設定參數與排程。`

## 對齊提醒

- Item 編號要同報價表一致（報價寫 `<Ref. to SOW Detail - Item N>`）
- 數量上限（5 台裝置、100 份文件、100 組問答、30 mandays）全部要寫，唔可以只出現喺報價表
