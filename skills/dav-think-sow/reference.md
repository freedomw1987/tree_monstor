# Dav Think SOW — Reference

> 本檔為 dav-think-sow 的參考資料附件，按需查閱。主檔在 `SKILL.md`。

## §1 6 核心維度（必問）

1. **項目背景與目的** — 問：做咩、服務邊個、解決咩問題、成敗點睇
   - 落點：md 開頭「背景與目的」段（唔放入 Item）
   - 收斂提示：對方講「要智能啲」→ 追問「用戶做完之後少做咩步驟」
2. **產品模組與功能範圍** — 問：有咩產品／模組，每個做咩、包含咩子功能
   - 落點：Item 的「Description」；模組型 Item 用 `A.`／`B.`／`C.`／`D.` 分塊逐個模組承載（唔開 Modules 欄）
   - 收斂提示：逐模組問「用戶喺呢個模組做咩動作」
   - 自家產品：公司自家產品 → 授權範圍寫「授權 Item」，部署與調試另寫「服務 Item」（見 §4.9）
3. **服務工作項與交付物** — 問：有咩服務、交付咩實物或報告、幾多步、做幾耐
   - 落點：服務型 Item；每項寫「交付物 ＋ 數量 ＋ 步驟」
   - 自家產品：部署、初始化、調試、驗收、培訓 → 獨立「部署與調試」服務 Item
4. **數量與上限** — 問：device 數／licence 數／角色數／文件數／問答數／mandays／同時用戶上限
   - 落點：Description 內寫明「含 N 個／上限 N／支援 N 台」
   - 收斂提示：必問「超出咗點計費」→ 答案寫入 Assumption
5. **假設與客戶責任** — 問：部署邊度、邊個出機器或 GPU 或環境或素材、依賴邊啲外部系統
   - 落點：Assumption 段（三類，見 §5）
6. **排除項 Out of scope** — 問：有咩明確唔做
   - 落點：Out of scope 段

## §2 補充維度（觸發式；觸發咗要喺對話列明）

1. **非目標** — 觸發：出現「順便加埋」「之後可能都要」
2. **Persona／多角色** — 觸發：管理員 vs 一般使用者、內部 vs 外部
3. **邊界情況** — 觸發：輸入有上下限、檔案格式限制、語言數量
4. **風險與依賴** — 觸發：高成本、不可逆、跨系統整合、幾個 Item 有先後次序
5. **待確認問題** — 觸發：有題答唔到 → 記入 md「待確認」段，唔好自己作
6. **合規與資料** — 觸發：客戶敏感資料、跨境、私隱、肖像與聲線版權
7. **授權與部署拆分** — 觸發：涉及公司自家產品授權、客戶要求分開報價 → 授權（License）與部署調試（Deployment & Setup）分開列 Item

## §3 成熟度評估（寫之前必跑）

- **涵蓋率** — 0：只講 1 維度｜1：講 2-3 維度｜2：核心 6 維度齊｜3：核心 6 ＋ 觸發咗嘅補充 ≥3 條
- **清晰度** — 0：抽象｜1：部分具體｜2：全部具體但冇量度｜3：全部具體 ＋ 可量度 ＋ 可觀察
- **可行性** — 0：冇考慮技術風險｜1：有想過但冇驗證｜2：有把握或已驗證｜3：有 PoC 或現成方案
- **規則** — 3 維度都 ≥2 → 可寫；任一 = 0 → 必須繼續問；任一 = 1 → 可寫但要備註 ⚠️「需求成熟度不足」
- **維度同 Item 嘅對齊** — 背景、排除項、待確認唔變 Item；只有「要交付嘅嘢」先變 Item

## §4 Item 類型與寫法

1. **產品功能型**（例：數字人互動應用）
   - 寫法：互動流程控制／動作控制／跨裝置／模型串接／知識庫與 Agent 調用
   - 常見漏：授權對象、裝置數、是否含模型授權
2. **平台模組型**（例：AI Agent 平台多模組）
   - 寫法：一個 Item；Description 用 `A.`／`B.`／`C.`／`D.` 分塊，每塊一個能力範疇標題，塊內用「功能名 — 說明」列舉細項；**唔另開 Modules 欄**
   - 常見漏：每塊都要有功能類別，唔好淨寫一句「支援 X」
3. **部署配置型**
   - 寫法：部署邊啲服務、邊啲資料庫、初始化規則；明確 on-prem 定 cloud
   - 常見漏：邊個出機器同 GPU；初始化規則（例如回答語言跟用戶語言）
4. **客製化型**（擬真角色、錄影、聲線）
   - 寫法：製作物清單 ＋ 數量 ＋ 素材由邊度嚟
   - 常見漏：素材提供方、拍攝安排、肖像與聲線授權
5. **數據／內容服務型**
   - 寫法：步驟（索引分塊 → prompt 工程 → 分類設計）＋ 涵蓋文件數上限
   - 常見漏：文件格式、圖片處理、數量超出點計
6. **評估／優化服務型**
   - 寫法：評分維度（off-topic／irrelevant／太長／太短）＋ 人工 vs Agent Judge ＋ 報告交付物 ＋ 題庫數
   - 常見漏：準確率門檻、每輪幾長、報告格式
7. **維護型（可選）**
   - 寫法：只寫 SLA 等級 ＋ 響應時間 ＋ token 數量 ＋ 引用維護條款，唔好抄全文
   - 常見漏：維護屬唔屬首年、SLA 級別要點對應
8. **分塊寫法** — 原 `Modules` 欄內容一律併入 Description，用分塊結構承載
   - 何時用：平台模組型必用；其他 Item 類型如能力範疇 ≥3 項亦建議用
   - 塊標題：`A.`／`B.`／`C.`／`D.` 順號 ＋ 能力範疇名（可加括號註明性質，如「（核心能力）」）
   - 塊內細項：`- <功能名> — <一句話說明>`，功能名用名詞短語，說明用完整書面語句子（完整範例見同套 `examples/sow-details-example.md`）
   - 塊尾／塊內適當位置補數量或限制：「包含 N 個／上限 N 個／支援 N 台」
9. **自家產品授權型**（公司自家產品；**必須拆成兩個 Item**）
   - **Item A — <產品名稱> 授權（Software License）**：寫授權範圍、授權模組、對象與角色、數量（台／用戶／並發）、授權年期、升級與續約政策
   - **Item B — <產品名稱> 部署與調試（Deployment & Setup）**：寫部署範圍（安裝、初始化、參數設定）、調試（測試、調校、聯調）、驗收交接；必寫交付物 ＋ 工作量（mandays）
   - **收費行項對應**：兩項分別對應報價表嘅獨立行項（License line／Service line）；SOW 內唔寫金額，授權 Item 註明「授權費用於報價表獨立列示」
   - **常見漏**：冇寫授權年期或數量、部署調試冇獨立成項、兩項混寫喺同一 Item（令報價無法分列）

## §5 Assumption 三類

- **環境與資源** — 部署位置、邊個出機器、邊個出 GPU 同模型授權、依賴外部系統
- **範圍與計算基準** — mandays 點計、超出點計費（費率與上限）、文件數同問答數係咪上限
- **商業假設** — 授權年期、續約、交付後變更點計；自家產品另寫升級政策與報價表 License 行項對應
- **未列明事項（通用必備）** — 任何未於本文件列明之服務均不包含於本次交付範圍；英文原文：`Any services not specified above are excluded.`（按文件語言書寫；中文本用書面語表述）

## §6 寫入 Excel（預設必出；跟固定 template）

- **預設**：每次產出 SOW md 時，**同時**產出 `docs/sow/<client>-<project>-<year>-sow.xlsx`，結構必須跟用戶提供之 Excel template（以最新 template 為準）
- **例外**：用戶明確只要 markdown、不要 Excel → 可省略，並在對話註明
- **固定 sheets（順序）**
  1. `Quotation` — 報價支援頁：**結構跟 template 保留**（客戶、區域、貨幣等表頭；明細列 `Item`／`Description`／`Man day`／`SKU`）；
     Description 用 `<Ref. to SOW Detail - Item N>` 對齊 SOW Details 編號（可按服務拆 1.1／1.2…）；`Man day` 可留空待用戶填
  2. `SOW Details` — 英文版範圍明細
  3. `SOW Details CN` — 中文書面語版範圍明細（對外中文以此為準）
- **`SOW Details`／`SOW Details CN` 固定欄位（只有四欄）**：`#`｜`Item`｜`Description`｜`Mandays`
  - **徹底唔開 `Module` 欄**：套用 template 後若仍有 `Module` 欄，必須整欄刪除（`delete_cols`），唔係清空內容
  - **一個 Item 一行**：`#`／`Item`／`Description` 同列填寫；唔再按模組拆多行
  - `Description`：職責說明 ＋ `A.`／`B.`／`C.`／`D.` 分塊（塊內 `-` 列點）＋ 交付物 ＋ 數量上限／限制；儲存格內換行；唔用 markdown 表格／`**` 粗體標記
  - `Mandays`：**一律留空**，畀用戶自己評估填寫；唔寫「待確認」／`TBD`／數字／SUM
- **自家產品** — 授權與部署調試分兩個 Item；Item 名標註「（Software License）」與「（Deployment & Setup）」；
  `Quotation` 分別 `<Ref. to SOW Detail - Item N>`
- **寫入／套用 template**：先複製 template 再覆寫內容，保留樣式；若寫入客戶既有報價簿，先確認路徑＋sheet＋欄位，
  `data_only=True`／`False` 各讀一次，**唔准覆蓋有公式嘅格**；Sheet 唔存在 → 先問用戶
- **唔寫金額**；寫後必驗：三個 sheet 齊、Item 編號同 md／Quotation 引用一致、CN／EN **Item 列數對齊**、兩邊皆無 `Module` 欄、`Mandays` 全空

## §7 交付格式與語言

- **語言** — 跟目標客戶／報價文件語言；用戶可指定
- **中文寫法** — SOW 內文一律用書面語（禁用字眼對照見 §8）；對話同提問可用口語
- **產出三份（預設）**
  - 工作版：含「待確認」、內部註記、假設草案 → `docs/sow/<client>-<project>-<year>-sow.md`
  - 交付版：淨留對外文字（去走待確認同內部註記）→ `docs/sow/<client>-<project>-<year>-sow-delivery.md`
  - Excel：跟 template → `docs/sow/<client>-<project>-<year>-sow.xlsx`（`Quotation`／`SOW Details`／`SOW Details CN`；見 §6）
- **命名** — 檔名用客戶 ＋ 項目 ＋ 年份，例如 `wynn-ai-muse-2026-sow.md`／`.xlsx`
- **唔寫死金額** — 只寫工作量（mandays）同數量上限；定價屬報價流程

## §8 書面語規範（SOW 內文）

- **適用範圍** — 工作版／交付版全文、Item 名、Description、Assumption、Out of scope、交付物與工作量說明、Excel `Description` 欄；同用戶問答同內部討論不受限（可用口語）
- **原則** — 繁體中文書面語；完整句式、名詞化、可驗證；唔用粵語助詞、語氣詞、縮寫口語
- **禁用字眼對照**（口語 → 書面語）
  - 「搞／整／做咗」→ 「開發／建置／完成」；「有／冇」→ 「包含／不包含」、「提供／未提供」
  - 「嘅」→ 「的」；「喺度」→ 「於」；「呢個／嗰個」→ 「本項／該項」
  - 「咁／咁樣」→ 「因此／如此」；「啲」→ 「若干」
  - 「唔」→ 「不」；「仲要」→ 「另需」；「要點」→ 「如何」
  - 「交返／搞掂」→ 「交付／完成並通過驗收」
  - 「頂住／handle」→ 「支援／處理」；「睇／諗」→ 「檢視／評估」
- **允許保留** — 產品名、專有名詞、縮寫同英文術語可原文保留（on-premise、AI Agent、RAG、mandays、Item）；客戶慣用名稱照客戶寫法
- **語氣** — 陳述式、客觀、對外一致；避免第一人稱「我哋」、避免宣傳形容詞（「好好用」「超強」「勁爆」）
- **稱呼** — 全份統一用「甲方／乙方」或「客戶方／服務提供方」，唔混用
- **反例** — 壞：「整好個 AI 客服，功能好齊」；好：「建置 AI 客服模組，涵蓋多輪對話、知識庫檢索與工單轉派」

## §9 自查清單（交付前逐項過）

- 每個 Item 都有「做咩 ＋ 包含咩」，冇空泛形容詞（支援／完善／優化／提升體驗）
- 服務 Item 有交付物 ＋ 數量上限
- Assumption 三類齊（或已寫明因咩而簡化）
- Assumption 段有通用排除條款「未列明之服務均不包含」（英文：`Any services not specified above are excluded.`）
- Out of scope 有內容（至少 2-3 條）
- Item 編號同報價或同其他文件雙向對得上
- 冇寫未同客戶確認嘅承諾（日期、數量、效能指標）；「待確認」有列出 ＋ 冇自己作
- 中文內文全部書面語（逐句對照 §8 禁用字眼清單）；英文只留專有名詞
- md Description 用 `A.`／`B.`／`C.`／`D.` 分塊；Excel 版同樣把分塊寫入同一格 `Description`（**無 Module 欄**；一個 Item 一行；`Mandays` 留空）
- 自家產品已拆成「授權」＋「部署與調試」兩個 Item，各自對應報價表獨立行項
- 授權 Item 寫明授權數量、年期、升級／續約；部署 Item 寫明交付物 ＋ 工作量（mandays）
- 語言一致、冇中英無規則夾雜；冇寫死金額
