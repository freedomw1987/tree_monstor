# Dav Planner — Reference（提問 / 維度 / 需求成熟度）

> 本檔為 dav-planner 的參考資料附件，於規劃過程中依需要查閱。主檔在 `SKILL.md`。

## §2 提問技巧細節（完整版）

### §2.1 問題類型

- **開放式** — 何時用：探索未知領域；範例：「你想要什麼效果？」
- **封閉式／二選一／多選題** — 何時用：確認收斂／強烈對比／多種可能；範例：「A 還是 B？」「用方案 A 還是 B？」「你想做 X / Y / Z 哪些？」

### §2.2 選項設計原則（V02 執行細節）

- 必含「⭐ 推薦」標示，且放第 1 個
- 選項 2-4 個（不超過 4）
- 描述必含「做了會發生什麼」+ 「為什麼這個」
- 不可隱藏用戶可選的「其他」（用 Type something）

### §2.3 追問節奏

- 開放式 → 封閉式 → 二選一（漸進收斂）
- 每輪結束必總結「目前已知」
- 避免「為追問而追問」（3-5 輪內收斂）

### §2.4 常見陷阱（自我檢查清單）

- ❌ 一次問 4 個問題；❌ 假裝完成（用戶還沒驗收就寫 Backlog）；❌ 過度分析（為分析而分析）
- ❌ SWOT 在不該用時強用；❌ 假設用戶懂技術術語

### §2.5 何時要任務升級（強制條款）

- 觸發條件：超出 dav-planner scope（用戶要做程式修改 / 系統部署）
- 動作：明示「這超出我的 scope，建議走 §2.3 Execution」

### §2.6 SWOT 分析決策點

- **觸發條件**（符合任 1 個即觸發；OR 不是 AND）：
  - 用戶表達強烈不確定（「不確定」「考慮中」「猶豫」）
  - 多方案競爭（3+ 候選方案）
  - 高風險 / 高成本決策
  - 用戶明確要求
- **不該觸發**：已有明確方向、簡單任務、時間緊急
- **4 象限標準格式**：S（優勢）/ W（劣勢）/ O（機會）/ T（威脅）各 1 行，每象限 ≤ 20 字

## §3 維度展開（完整版）

> ⚠️ **唔寫總數**：核心 4 ＋ 補充維度會隨需求種類長（加維度唔應該再要改 4 處名稱）。
> 判斷標準睇下面兩組，唔係數幾多條。

### 核心 4 維度（必問）

1. **用戶與場景** — 誰用？什麼情境？
2. **目標與痛點** — 為什麼做？解決什麼？
3. **流程與操作** — 怎麼用？流程？
4. **成功標準** — 怎麼算「做對了」？

### 補充維度（視情境 / 觸發條件展開）

> **每條都有觸發條件**：Agent 逐條對住條件判斷，**並喺對話中列出「今次觸發咗邊幾條補充維度」**
> （用戶可以直接話「呢條唔使問」→ 從清度走）→ 需求成熟度「涵蓋率」就係按呢份清單計。

1. **Non-goals** — 不做什麼？｜觸發：容易無限擴張、需求講「順便加埋」
2. **Persona** — 目標用戶輪廓｜觸發：涉及唔同角色（管理員 vs 一般用戶）
3. **Edge cases** — 邊界情況｜觸發：輸入有上下限、有空值／極端值
4. **Risks** — 風險｜觸發：不可逆、高成本、影響錢／合規
5. **Open questions** — 待釐清問題｜觸發：有任何一題答唔到
6. **業務邏輯與依賴** — 有咩規則要守？依賴邊啲嘢先做得？

   **何時必問**（符合任一即問；唔好因為「唔係核心 4」而跳過）：
   - 有計算 / 規則（金額、稅、折扣、權限、狀態機、冪等、上限）
   - 依賴其他模組、服務、外部系統或資料來源（跨 Module、INT US）
   - 幾個 US 之間有先後次序（邊個要先行）

   **問法（V01／V02）**：一題一輪、2-4 個選項、⭐ 推薦放第 1 個；建議**最後問**
   （要先知做咩，才知有咩規則同依賴）。

   例：「呢個功能嘅業務規則同依賴，你點睇？
   ⭐ A（推薦）：規則我照你講寫入 AC，依賴填入『依賴』欄 ｜ B：只寫 AC 規則，依賴口頭講 ｜ C：兩樣都先唔寫」

   **答案落點**（問完一定要寫落文件，唔可以只留喺對話）：
   - 業務規則 → AC 嘅 Given-When-Then 條款 ＋ Backlog 詳細段「**業務規則**」行
   - 依賴 → Backlog 表格「依賴」欄 ＋ Backlog 詳細段「**依賴**」行

   **答唔到點算**：用戶未決定 → 寫成「待確認（列入 Open questions）」，唔好自己作。

## §5 需求成熟度評估（寫 Backlog 前必跑）

- **涵蓋率** — 0 分：只講 1 個維度｜1 分：講 2~3 維度｜2 分：講核心 4 維度｜3 分：講核心 4 ＋ **觸發咗嘅**補充維度 ≥ 3 條
- **清晰度** — 0 分：抽象｜1 分：部分具體｜2 分：全部具體但沒量度｜3 分：全部具體 + 可量度 + 可觀察
- **可行性** — 0 分：沒考慮技術風險｜1 分：有想過但沒驗證｜2 分：已做 Spike 或有把握｜3 分：已有 prototype 或現成方案

**規則**：
- **「觸發咗嘅補充維度」＝ Agent 按上面每條嘅觸發條件逐條判斷後列出嘅清單**（要喺對話中列明，
  用戶可覆核）；觸發咗但冇問 → 該維度**唔算**已涵蓋（會拉低涵蓋率分數）
- 3 維度都 ≥ 2 分 → 可寫 Backlog
- 任一維度 = 0 分 → 必須繼續提問
- 任一維度 = 1 分 → 可寫但備註 ⚠️「需求成熟度不足」
