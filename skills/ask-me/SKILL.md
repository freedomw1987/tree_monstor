# Ask Me

## TL;DR

1. **做什麼**：trust mode 結束後，讀 `docs/need-you-help.md`（專案端路徑）把 ☐ 未確認的擔憂**一個一個**問用戶、確認後**雙寫**（要法 `need-you-help.md` + `docs/backlog.md`），全部處理完才退出。
2. **何時觸發**：用戶說「處理 need-you-help」「ask-me」「跑完需要我幫的子問題」、trust mode 自然結束後有遺留擔憂。
3. **不適用於**：trust mode 進行中（打斷 trust）、一般對話提問（用 ask_user_question 就好）、純諮詢（用戶只是問問題不需決策）。
4. **關鍵紀律**：
   - **逐題確認**：一次只問 1 個擔憂（V01 一次一個問題）
   - **雙寫必齊**：用戶回答後，`need-you-help.md` 和 `backlog.md` 必須**同步**更新，缺一不可
   - **退出條件**：全部 ☐ 都變 ☑ 才輸出 `🏁 ask-me 結束`
   - **不自動延伸**：結束後不自動做事、等用戶指示（見同套上游 skill 結束後行為規範，需同套安裝）
5. **必產出物**：`docs/need-you-help.md` ☐→☑ 全確認 + `docs/backlog.md` 對應 US 狀態更新 + 對話輸出處理總結。

## 觸發時機

| 情境 | 觸發 |
|------|------|
| 用戶說「ask-me」「處理 need-you-help」「跑一下要問我的」| ✅ 必須 |
| Trust Mode 自然結束（deadline 到）+ `need-you-help.md` 有 ☐ | ✅ 自動建議（不在對話中自動啟動）|
| Trust Mode 結束標記後用戶說「看看要問的」| ✅ 觸發 |
| Trust Mode 進行中用戶提問 | ❌ 不觸發（打斷 trust，走普通對話）|
| 一般任務的單次提問 | ❌ 用 `ask_user_question` |
| 純諮詢（用戶只是問、不需決策）| ❌ 用普通對話回應 |

## 流程（4 步）

### Step 1：讀 need-you-help.md

- **動作**：
  1. 讀 `docs/need-you-help.md` 全文（專案端路徑）
  2. 列舉所有 `- [ ] ...` 未確認條目（跳過 `- [x]` 已確認）
  3. 若 0 個 ☐ → 輸出「無未確認擔憂」+ 退出
- **為什麼**：避免「沒東西還硬問」、保證主流程有意義
- **產出**：未確認擔憂清單（帶 context：US 編號、擔憂內容、影響範圍、建議）
- **證據**：對話輸出 `共 N 個未確認擔憂，待處理`

### Step 2：逐題問用戶

- **動作**：
  1. 取清單第 1 個 ☐、顯示完整 context（US 編號、擔憂、影響、建議）
  2. 用 `ask_user_question` 問 4 選項（**V02 必標推薦**）：
     - **⭐ 最推薦 繼續做**，原因：用戶先前在 trust mode 期間沒明確拒絕、繼續做風險最低且保留原方案累積的進度
     - **改設計**：用戶給新方向
     - **跳過**：不做這個 Backlog
     - **自訂**：用戶輸入其他決定
  3. 若用戶選「自訂」→ 用 free-form 文字回答、Agent 視為自訂決定
- **為什麼**：V01 一次一題；固定 4 選項降低用戶決策成本（見 monorepo 對應的格式範本，路徑由 monorepo 約定）
- **產出**：用戶的決定 + 理由
- **證據**：對話有 `⚠️ US-XXX 擔憂` + 4 選項 + 用戶回答

### Step 3：雙寫紀錄（必齊）

- **動作**（兩個檔案**必同步**更新、缺一不可）：
  - **3a. 寫 `docs/need-you-help.md`**：
    - 把**用戶選的那個** `- [ ]` 變 `- [x]`（**只勾用戶選的那個、其他 ☐ 保留**，避免誤會為全勾）
    - 在被勾的 `- [x]` 後加 emoji 前綴（`✅` 繼續做 / `📝` 改設計 / `⏸️` 跳過）+ 抉擇理由行 `**抉擇理由（YYYY-MM-DD）**：<用戶給的理由>`
    - **自訂分支**：若用戶選「自訂」→ 在抉擇區**追加一行** `- [x] 📝 自訂決定（<用戶 free-form 文字>）`，原 3 個 checkbox 維持 ☐
  - **3b. 寫 `docs/backlog.md`**：
    - 對應 US/Story 行的狀態欄：⏸️ 待確認 → `✅ 已確認`（繼續做）/ `📝 改設計`（改設計）/ `📝 自訂決定`（自訂）/ `⏸️ 跳過`（跳過）
    - 表格下方加註腳 `> 📝 YYYY-MM-DD ask-me：<抉擇理由>`
    - orphan 情況（US 在 backlog.md 找不到）→ backlog.md 不動、結束時提醒用戶手動處理
  - **失敗處理**：若 3a 或 3b 任一寫入失敗 → 不勾 `- [x]`、回報用戶 + 標 `⚠️ 雙寫半完成（需人工修）`、不繼續下一題
- **為什麼**：雙寫是 ask-me 的核心紀律 — 只寫一邊會造成 need-you-help 和 backlog 不同步、未來難追溯
- **產出**：`need-you-help.md` 有新 ☑ + `backlog.md` 有新 emoji 狀態 + 理由註腳
- **證據**：兩個檔案都有對應的當下時間戳變更

### Step 4：下一題或退出

- **動作**：
  - 若清單還有 ☐ → 回到 Step 2
  - 若清單 0 個 ☐ → 輸出 `🏁 ask-me 結束` + 處理總結（N/M 項、每項決定簡述、建議下一步）
  - **退出條件定義**：「全部 ☐ 變 ☑」包含 **orphan 擔憂**（雖 backlog.md 無對應 US、但 need-you-help.md 已 ☐→☑）— orphan 仍算完成、不會留下遺留 ☐
- **為什麼**：全部處理完才退出 — 避免「還有 ☐ 但假裝完成」
- **產出**：
  - 處理總結 Markdown（含每項決定、含 orphan 數）
  - 對話輸出 `🏁 ask-me 結束` + 提示「可重啟 trust mode 帶著新狀態續做」
- **證據**：對話有 `🏁 ask-me 結束` 字樣

## 規則 / 例外 / 限制

| 規則 | 例外 | 限制 |
|------|------|------|
| 一次只問 1 題 | N/A | V01 紀律、批量會增加決策疲勞 |
| 雙寫必齊（need-you-help + backlog）| N/A | 缺一即視為 ask-me 未完成 |
| 全部 ☐ 變 ☑ 才退出 | 用戶中途叫停可提早退出 | 退出時標 `⏸️ 用戶中斷` |
| 不動 `need-you-help.md` 以外的需求檔 | N/A | 只動 need-you-help + backlog，不改需求 / 設計相關文件 |
| 不自動延伸（結束後不做事）| 用戶說「繼續 trust」可重啟 | 見同套上游 skill 結束後行為規範（需同套安裝） |
| 退出後不重做 trust mode | N/A | trust 重啟由用戶決定 |
| 信任標記 `✅/📝/⏸️` 三選一 | 不用其他 emoji 保持一致性 | 與 backlog 既有 emoji 對齊 |
| 抉擇理由必含日期 | N/A | `YYYY-MM-DD ask-me：...` 格式便於 grep |
| 對應 US 在 backlog.md 找不到 | 標 `⚠️ orphan` 在 need-you-help、不阻塞流程 | 結束時提醒用戶手動處理 |
| **不走完整 SOP**（§2.1→§2.5）| N/A | ask-me 是輔助 skill、§2.6 簡化流程 |

## 與上游 skill 的關係

| 階段 | 上游 skill | 本 skill |
|------|-----------|---------|
| **上游 trust mode 進行中** | Agent 寫 `need-you-help.md` ☐ 條目 | ❌ 不觸發 |
| **上游 trust mode 結束後** | 結束標記輸出（見同套上游 skill 結束後行為規範，需同套安裝）| ✅ 等待用戶說「ask-me」 |
| **本 skill 結束後** | N/A | 對話輸出 `🏁 ask-me 結束`，等用戶說「繼續 trust」或新指示 |

> 本 skill 不是上游 trust skill 的一部分、是獨立 skill；雙方透過 monorepo 約定的待辦檔案介接（路徑由 monorepo 約定）。
