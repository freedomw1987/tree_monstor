# Ask Me — 流程細節（4 步）

> 本檔為 `ask-me` skill 的子檔，逐Step 寫「動作 / 為什麼 / 產出 / 證據」。入口在同套 `SKILL.md`。

## Step 1：讀 need-you-help.md

- **動作**：
  1. 讀 `docs/need-you-help.md` 全文（專案端路徑）
  2. 列舉所有 `- [ ] ...` 未確認條目（跳過 `- [x]` 已確認）
  3. 若 0 個 ☐ → 輸出「無未確認擔憂」+ 退出
- **為什麼**：避免「沒東西還硬問」、保證主流程有意義
- **產出**：未確認擔憂清單（帶 context：US 編號、擔憂內容、影響範圍、建議）
- **證據**：對話輸出 `共 N 個未確認擔憂，待處理`

## Step 2：逐題問用戶

- **動作**：
  1. 取清單第 1 個 ☐、顯示完整 context（US 編號、擔憂、影響、建議）
  2. 用 `ask_user_question` 問 4 選項（**V02 必標推薦**）：
     - **⭐ 最推薦 繼續做**，原因：用戶先前在 trust mode 期間沒明確拒絕、繼續做風險最低且保留原方案累積的進度
     - **改設計**：用戶給新方向
     - **跳過**：不做這個 Backlog
     - **自訂**：用戶輸入其他決定
  3. 若用戶選「自訂」→ 用 free-form 文字回答、Agent 視為自訂決定
- **為什麼**：V01 一次一題；固定 4 選項降低用戶決策成本（見 monorepo 對應的格式範本，路徑由 monorepo 約定）
- **產出**：用戶的決定 + 理由
- **證據**：對話有 `⚠️ US-XXX 擔憂` + 4 選項 + 用戶回答

## Step 3：雙寫紀錄（必齊）

- **動作**（兩個檔案**必同步**更新、缺一不可）：
  - **3a. 寫 `docs/need-you-help.md`**：
    - 把**用戶選的那個** `- [ ]` 變 `- [x]`（**只勾用戶選的那個、其他 ☐ 保留**，避免誤會為全勾）
    - 在被勾的 `- [x]` 後加 emoji 前綴（`✅` 繼續做 / `📝` 改設計 / `⏸️` 跳過）+ 抉擇理由行 `**抉擇理由（YYYY-MM-DD）**：<用戶給的理由>`
    - **自訂分支**：若用戶選「自訂」→ 在抉擇區**追加一行** `- [x] 📝 自訂決定（<用戶 free-form 文字>）`，原 3 個 checkbox 維持 ☐
  - **3b. 寫 `docs/backlog.md`**：
    - 對應 US/Story 行的狀態欄：⏸️ 待確認 → `✅ 已確認`（繼續做）/ `📝 改設計`（改設計）/ `📝 自訂決定`（自訂）/ `⏸️ 跳過`（跳過）
    - 表格下方加註腳 `> 📝 YYYY-MM-DD ask-me：<抉擇理由>`
    - orphan 情況（US 在 backlog.md 找不到）→ backlog.md 不動、結束時提醒用戶手動處理
  - **失敗處理**：若 3a 或 3b 任一寫入失敗 → 不勾 `- [x]`、回報用戶 + 標 `⚠️ 雙寫半完成（需人工修）`、不繼續下一題
- **為什麼**：雙寫是 ask-me 的核心紀律 — 只寫一邊會造成 need-you-help 和 backlog 不同步、未來難追溯
- **產出**：`need-you-help.md` 有新 ☑ + `backlog.md` 有新 emoji 狀態 + 理由註腳
- **證據**：兩個檔案都有對應的當下時間戳變更

## Step 4：下一題或退出

- **動作**：
  - 若清單還有 ☐ → 回到 Step 2
  - 若清單 0 個 ☐ → 輸出 `🏁 ask-me 結束` + 處理總結（N/M 項、每項決定簡述、建議下一步）
  - **退出條件定義**：「全部 ☐ 變 ☑」包含 **orphan 擔憂**（雖 backlog.md 無對應 US、但 need-you-help.md 已 ☐→☑）— orphan 仍算完成、不會留下遺留 ☐
- **為什麼**：全部處理完才退出 — 避免「還有 ☐ 但假裝完成」
- **產出**：
  - 處理總結 Markdown（含每項決定、含 orphan 數）
  - 對話輸出 `🏁 ask-me 結束` + 提示「可重啟 trust mode 帶著新狀態續做」
- **證據**：對話有 `🏁 ask-me 結束` 字樣
