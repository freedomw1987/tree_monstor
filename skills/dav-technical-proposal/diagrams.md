# Dav Technical Proposal — 架構圖

> 本檔承載「做架構圖」嘅能力：邊一節要畫邊種圖、點寫先渲染得出、圖檔點交付。
> 產出位置：**只喺 2. Technical Solution 單元**（2.1／2.2.1／2.4／2.6.3），唔散落喺背景同實施章節。
> 兩條路線：**基線＝Mermaid 寫入正文**（零依賴、任何環境跑得）；**升級＝互動式架構圖**（見 §5，需另裝外部 skill）。

## §1 圖種對應（**有內容先畫**）

- **2.1 System Technical Architecture** — 系統架構圖（`graph TB` 分層）：分層（前端／後端／整合／基建）、組件關係、對外接口、資料流
- **2.2.1 User Surface** — 主要操作流程圖（`graph LR`）：每類使用者嘅入口 → 主要操作 → 結果；只畫主路徑，唔畫所有分支
- **2.4 Infrastructure Requirement** — 基礎設施拓撲圖（`graph TB`）：環境邊界、負載平衡／應用／資料區、網絡區段、第三方服務
- **2.6.3 Migration Process** — 遷移流程圖（`graph LR`）；需要講清對賬時序先用 `sequenceDiagram`，唔好兩種都畫
- **2.3 Non Functional Requirement** — 可選：容量／流量模型圖（`graph LR`）；冇量化資料就唔畫
- **唔畫嘅情況** — 冇資料／資料未確認／只為「睇落完整」→ 唔畫；喺該節寫明「圖待補：需要咩資料先畫得」

## §2 每張圖嘅內容要求（逐項過）

- **有標題** — 圖前一行寫 `- **圖 N — <圖名>**`（用列表項，唔好寫成淨一行粗體），序號跟章節順序（圖 1、圖 2…），交付版引用得到
- **有圖例** — 節點按類型著色（前端／後端／整合／基建／外部），並於圖下用一行講明顏色含義
- **節點名同正文一致** — 圖上嘅模組名、系統名一定要同 2.2.2／2.4 正文用同一個名，唔准圖文兩套名
- **節點標籤＝名稱 ＋ 職責** — 唔好淨寫名；`["交易對賬服務<br/>逐筆對賬與差異標記"]`
- **邊有方向** — 箭頭標資料流方向；可選／非同步路徑用虛線 `-.->`
- **圖唔代替文字** — 圖後保留文字解說段（架構圖後要有「資料流」說明）
- **圖上唔涉密** — 唔寫密碼、連線字串、內網 IP、機房機號、客戶真實識別資料

## §3 Mermaid 語法防錯（渲染炸點，逐條避）

- **括號**：文字含 `(` `)` → 整句用雙引號包住，例 `A["交易服務（核心）"]`；資料庫柱體寫 `pg[("PostgreSQL 15")]`
- **引號**：文字入面唔好用英文雙引號 → 改用「」『』
- **數字加點**：文字唔好寫 `1. 感知`（會被當 list 語法）→ 寫 `1.感知`／`① 感知`／`(1) 感知`
- **subgraph**：一律 `subgraph fe["前端層"]`（ID ＋ 引號顯示名）；引用時用 ID `fe`，唔用顯示名
- **節點 ID**：只用英數字 ＋ 底線；唔用 `end`、`graph`、`class`、`subgraph` 做 ID
- **換行**：節點內換行用 `<br/>`，唔好直接斷行；**唔好用 `<>` 做佔位符**（`<` 會被當 HTML 標籤）
- **箭頭**：`-->` 主流程、`-.->` 可選／非同步、`==>` 主幹強調；邊上標籤寫 `-->|交易資料|`
- **著色**：統一用 `classDef` ＋ `class`／`:::`；文字唔用 emoji；中文標籤避免用半角 `:`（同標籤語法衝突）
- **驗證**：出圖後必須確認渲染 —— 有 Mermaid CLI 就 `mmdc -i x.mmd -o x.svg`；冇就逐項對上面 8 條，並喺交付自查打勾

## §4 圖檔匯出與交付（Mermaid 基線）

- **真相係 code block** — 方案書 md 內嵌 ` ```mermaid ` 碼 block（Obsidian／GitHub／VS Code 直接渲染、可 diff、可版本控制）
- **需要圖檔時**（交 Word／PDF／PPT，或客戶唔收 md）：
  - 用 Mermaid CLI 匯出：`mmdc -i <name>.mmd -o <name>.png`（印刷用 `.svg` 或高 dpi `.png`）
  - 圖檔放 `docs/proposal/assets/<client>-<project>/`，檔名同 code block 對應
  - 交付版：保留 code block，並於圖下註明「圖檔：`assets/<client>-<project>/<name>.png`」
- **冇 CLI 嘅環境唔阻礙交付** — 保留 code block，並於交付說明提「圖檔需於具 Mermaid CLI 嘅環境匯出」
- **唔准** 用 ASCII 框圖代替（讀唔到、唔可 diff、版本追蹤差）

## §5 可選升級：互動式架構圖

- **基線唔變** — 方案書正文永遠以 Mermaid code block 為準（§4）；互動圖係**加碼**，唔係替代
- **適用場景** — 用戶／客戶要「點開即睇」嘅互動圖、方案演講展示、要導出長圖或 PDF、想沿路徑探索組件關係
- **工具** — 外部 skill `archify`（開源、Apache-2.0），會出**已驗證嘅獨立 HTML**（自帶版面／箭嘴／標籤避讓等檢查）；**需另行安裝**，未裝唔影響本 skill 運作
- **圖種對應**
  - 2.1 系統架構 → `architecture`；2.4 基礎設施（部署視角）→ `architecture`
  - 2.2.1 操作流程 → `workflow`；2.6.3 遷移流程 → `workflow`，講時序先用 `sequence`
- **輸入** — 可直接餵本 skill 已寫好嘅 Mermaid（避免重複描述、避免兩圖唔一致）；或餵自然語言描述
- **產出** — 獨立 HTML 檔放 `docs/proposal/assets/<client>-<project>/`；交付版於圖下註明檔名，並保留同一張 Mermaid code block
- **未裝時**
  - 唔阻礙交付：維持 Mermaid 基線，並於交付說明提「如需互動式架構圖，可另裝 `archify` skill（開源、Apache-2.0）」
  - 安裝指令：`npx -y skills@latest add https://archify.si --skill archify --agent <agent> --global --copy --yes`
- **邊界** — 互動 HTML 唔可以取代正文（客戶可能只收 md／Word）；Mermaid 圖同互動圖嘅節點名、分層、連線必須一致，唔一致以正文為準並重出互動圖

## §6 圖相關自查（併入交付前自查清單）

- 每張圖都有「圖 N — 名稱」標題，序號連續、無重複
- 圖種同章節對：2.1 架構圖／2.2.1 流程圖／2.4 部署圖／2.6.3 遷移流程圖
- 節點名同正文一致；每個節點有職責；圖後有文字解說
- §3 語法防錯 8 條逐項過；已用 Mermaid CLI 渲染驗證（若環境有）
- 圖上無秘密資料；圖內無未確認數字（未確認就唔畫，唔喺圖上標待確認）
- 交付版圖檔路徑存在（若已匯出）
- 有互動圖時：Mermaid 與互動圖內容一致；交付版兩者都有指向
