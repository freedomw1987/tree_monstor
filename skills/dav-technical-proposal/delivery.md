# Dav Technical Proposal — 交付與產出

> 本檔承載「點樣交出去」：交付版淨稿、Word／PDF 產出、改版時要同步嘅嘢、交付前嘅腳本化自查。
> 內容寫法在 `reference.md`；圖在 `diagrams.md`。

## §1 交付版淨稿（工作版 → 交付版）

- **用腳本生成，唔好手改** — 讀工作版 → 刪段落／改寫 → 寫交付版；腳本要可重複執行，改稿後重跑就係最新交付版
- **必刪**
  - 「待確認清單」整段（含表頭、說明段）
  - 所有內部註記（`<!-- 內部：… -->`、`<!-- Internal: … -->`）
  - 所有 `<>` 括號位（內部術語、待補資料）
  - 內部金額與商業條款（報價、licence 金額、供應商報價）—— 即使喺註記內都要刪
  - 工作版交叉說明（「交付版另存為 `xxx.md`」「本版已刪除待確認」）→ 改成交付版自己嘅說明（版本號、日期、對客定位）
- **必改寫** — 未確認但對客有風險者，喺交付版改寫成 Assumption 條文，例：「非功能指標將於詳細設計階段，經雙方確認後定案。」
- **必查（交付版乾淨度）**
  - 冇「SOW Item N」「見 PRD 第 X 章」「參見附件」「詳見《…》」「如前所述」式外部依賴 → 改寫成正文內容
  - 冇未同客戶確認嘅承諾（效能數字、上線日期、數量、授權年限）
  - 冇內部註記、冇待確認段、冇金額、冇舊語言殘留字元
  - 引外部標準要連具體要求一齊寫（唔准淨寫標準名）

## §2 Word／PDF 產出（Markdown → docx）

- **Markdown 係 source of truth** — docx／pdf 由 Markdown 產出；改稿只改 Markdown，然後重出；唔准手改 docx，否則兩版會唔一致
- **管線（3 步）**
  1. `pandoc` → docx：`--from=markdown+pipe_tables+link_attributes`、加 TOC、圖用 `![alt](path){width=Xin}`、資源路徑指向方案書目錄
  2. docx XML 修補（頁面尺寸、表格欄寬、橫向頁）
  3. `soffice --headless --convert-to pdf` 驗證（頁數、頁向、圖表數）
- **pandoc 陷阱（逐個處理）**
  - **頁面尺寸** — pandoc 預設係 Letter
    - docx body 層級最後一個 `<w:sectPr>` 若冇 `pgSz`／`pgMar`，要補 A4 直向（`w:w=11906 w:h=16838`、四邊 1440 twips），否則尾段變 Letter
  - **表格欄寬** — pandoc 全部等寬，長文字欄會被壓成 30 字
    - 要改 `<w:tblGrid>` 的 `<w:gridCol w:w>` ＋ 每格 `<w:tcW w:type="dxa">`，並加 `<w:tblLayout w:type="fixed"/>`
    - 欄寬按各欄最長內容比例分配（長度先開根號，避免一欄吃掉全表）
  - **圖說與圖同一段落** — pandoc 會把粗體圖說同緊接嘅圖合併成同一個 `<w:p>`；橫向頁要整段搬，唔好只搬圖
  - **圖片改名** — pandoc 會將 media 改名，用 MD5 對回原檔名再定位圖片段落
- **橫向頁插入** — 圖段落前後各插一個空段落帶 `sectPr`：前者 A4 直向（結束上一節）、圖段落、後者 A4 橫向（令圖自成一節）
- **圖尺寸計算** — 直向可用 6.3in × 9.7in、橫向可用 10.7in × 6.85in；圖嘅長寬比決定放直度定橫度（闊嘅橫度、瘦高嘅直度），寬高都要 ≤ 可用面積並留位俾圖說
- **交付兩份** — 工作版 docx（含待確認清單）＋ 交付版 docx（淨稿）；檔名同 Markdown 一致

## §3 改版同步清單（改咗邊樣，呢啲就要一齊改）

- **加章節／調章節順序** — 重編章節號 ＋ 圖號 ＋ 圖檔名 ＋ 正文所有「見 N.M」引用；**用腳本驗引用目標真係存在**（遞增重編好易漏，會出現「見 4.2.2」但章節只有 3.2.2）
- **改責任邊界／架構** — 正文 ＋ Mermaid 圖內文字 ＋ 圖例 ＋ Archify 候選 ＋ 互動圖說明，一齊改；圖同正文唔一致以正文為準
- **全語言轉換（中↔英）** — 正文、表格、圖說、圖例、Mermaid 節點／邊標籤、術語表、待確認清單、內部註記、文件抬頭、章節括號標題，全部要轉；轉完用 grep 掃殘留字元
- **改數字／規格** — 搜全部出現位置（正文、表格、圖內文字、圖說、待確認表）
- **圖檔改名／重出** — 圖檔名同「圖 N」對應；重出後驗來源同資產一致

## §4 交付自查（腳本化，交稿前跑一次）

- **章節** — 順序同編號連續、無重複、有插章節時編號已重編
- **引用** — 所有「見 N.M」「第 N 節」嘅目標章節都存在
- **表格** — 每張表各行列數一致；欄標題自我解釋；欄數 ≤6
- **術語表** — 每條術語正文都有用到（逐條核對，唔好淨靠目測）
- **交付版乾淨度** — 冇待確認段、冇內部註記、冇金額、冇外部依賴、冇舊語言字元
- **圖** — 每張圖有「圖 N — 名稱」、節點名同正文一致、圖後有文字解說；圖檔引用全部存在
- **圖檔一致性** — 由 Markdown 重新渲染 Mermaid，比對 SVG／PNG 資產（MD5 或 viewBox 比例）
- **Word（如果有出）** — 圖數＝預期、表格數＝預期、頁向正確（直向 + 橫向）、頁面全部 A4
- **產出物清單** — 工作版 Markdown ＋ 交付版 Markdown ＋ 圖檔目錄 ＋（可選）兩份 docx／pdf，全部喺 `docs/proposal/` 之下
