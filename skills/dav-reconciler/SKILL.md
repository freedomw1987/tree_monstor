# Dav Reconciler

## TL;DR
1. **做什麼**：把「用戶當初要什麼」與「這次真的做出什麼」逐條比對，產出**需求對帳表**。
2. **何時觸發**：§2.3 執行段結束、進入 §2.4 反省**之前**（Gate 4.5 需求對帳）。
3. **預設 SOP 路徑**：§2.3 尾段子閘（不是第五道大 Gate；四道大 Gate 定義不動）。
4. **關鍵紀律**：**獨立性**（對帳由未參與實作的 subagent 做，不准執行者自己對帳自己）；**硬門檻**（對帳沒全數對上 → 不得宣告「完成」）；**只給必要輸入**（不給對帳者實作過程的自述，避免被引導）。
5. **必產出物**：目標專案 `docs/reconcile/<US-ID>-reconcile.md`（需求對帳表）＋ 交付摘要裡的「需求對帳」段（摘要 + 連結）。

## 觸發時機
- **開發編程任務執行段完成、進 §2.4 前** → ✅ 必須
- **需求錨點檔存在且本次 US 有 R-ID** → ✅ 觸發前提
- **trust mode 進行中** → ⚠️ 見規則表（不中途停下問用戶）
- **純諮詢 / 一般任務（§2.6）** → ❌ 不觸發
- **存量 US（無需求錨點）** → ❌ 不觸發（無錨點可對）；**已進 §2.4 反省** → ❌ 太遲了（反省必須建立在已對帳的前提上）

## 流程（5 步）
- **Step 1 準備輸入（刻意做少）** → 對話內直接給對帳者：需求錨點檔全文 ＋ 最終變更清單（檔案 + diff）＋ 該 US 既有文件（AC 範本、backlog 該列）；唔落檔
- **Step 2 交給獨立 subagent 對帳** → 由**未參與本次實作**的 subagent 依 [`reconcile-format.md`](./reconcile-format.md) 產出對帳表；對話貼出對帳者原文
- **Step 3 檢查完整性（R-ID 覆蓋）** → 覆蓋率 = 已列 R-ID / 錨點 R-ID 總數，必須 100%；漏列 = 未對帳
- **Step 4 寫檔 + 回報** → 寫 `docs/reconcile/<US-ID>-reconcile.md`；回報結論（全部已實作 / 有部分 / 有未實作）
- **Step 5 交給交付摘要（狀態降級）** → 對帳有部分／未實作 → 交付狀態**不得**標「完成」，只可標「部分完成」＋待補清單

## 規則 / 例外 / 限制
- 對帳者必須**獨立 subagent**（未參與實作） — 例外：環境無 subagent 能力 → 降級為執行者自省對帳；限制：降級時對帳檔與交付摘要**必須**標註「對帳降級（無獨立 subagent）」，且不得宣告對帳通過
- **對帳表必須覆蓋全部 R-ID** — 例外：無；限制：漏一條即對帳不完整；不得視為「無需對帳」
- **狀態值僅 4 種（已實作／部分實作／未實作／已作廢）** — 例外：無；限制：不得自創第 5 種；格式詳見同套 [`reconcile-format.md`](./reconcile-format.md)
- **對帳未全數對上 → 不得標「完成」** — 例外：全部 ❌ 未實作 → 可標「未完成」；限制：其餘只能標「部分完成」並列出待補項
- **錨點的需求句數 = 0 → 對帳失敗** — 例外：無；限制：不得視為「無需對帳」；須回報「錨點無需求句」由人補正
- **給對帳者的輸入不含實作自述**；**trust mode 進行中不中途停下問用戶** — 例外：無／用戶叫停時立即收斂；限制：給了自述就失去獨立性；對帳結果照常產出，缺口記入 trust-log 代答 +
need-you-help 待回覆
- **不適用於沒有需求錨點的存量任務** — 例外：用戶明確要求時可手動補錨點；限制：手動補的錨點須標明來源為「代擬」
- **進 Gate 4.5 必引用 mandatory_phrase**（見 [`gate-4.5.md`](./gate-4.5.md)） — 例外：無；限制：不引用 = 視為 gate 未觸發（偽裝通過）
