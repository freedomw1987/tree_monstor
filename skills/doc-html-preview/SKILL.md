# Doc HTML Preview

> **Two HTMLs per MD: engineering version (1:1) + boss version (decision-focused).**

## Why this exists

`SOUL.md` 紅線 10 says: "**沒有文件的代碼不能 merge**" — every project must have `PROJECT-OVERVIEW.md / PRD.md / DESIGN.md / ADR / API.md / TEST-COVERAGE.md / TECH-DEBT.md` committed to git.

David needs to **read and confirm** these documents during **Think** and **Plan** phases. Two audiences:

1. **Developer / code review** — wants the full MD rendered faithfully
2. **David (the user / boss)** — wants a **decision-oriented summary** with:
   - One sentence "what is this?"
   - 3 emoji cards (幾耐 / 幾錢 / 避險)
   - Yellow box of "拍板事項" (3 yes/no questions with pros/cons)
   - Red box of risks in plain language
   - Links to engineering version for full details

This skill produces **both HTMLs side-by-side**, generated from the same MD. The boss version's structured content (cards/decisions/risks) comes from `docs/_meta/<doc>.json` — generated by the developer profile (or kanban CEO worker) reading the MD and producing a structured summary. Override possible via MD section.

## Conventions (frozen — do not change without David's approval)

| Aspect | Rule |
|--------|------|
| Source of truth | `~/www/<project>/docs/*.md` |
| Engineering HTML | `~/www/<project>/docs/_html/<doc-name>.html` |
| Boss HTML | `~/www/<project>/docs/_html/<doc-name>-boss.html` |
| Boss summary JSON (input) | `~/www/<project>/docs/_meta/<doc-name>.json` |
| Git status | **HTML and meta JSON are NOT committed.** `docs/_html/` AND `docs/_meta/` MUST be in `.gitignore` |
| MD override mechanism | If MD has `## 👀 老闆版摘要` section, that whole section is used as the boss body content (overriding JSON) |
| CSS | GitHub-like light/dark theme (engineering) + custom decision UI (boss). Both inline, no external assets |
| Tools | `pandoc` (already installed) + `python3` (already installed) |
| Server | **None.** HTML opens via `file://` |
| LLM calls | **Never inside `build.sh`.** Boss summary JSON is generated by the agent loop / kanban CEO worker separately. |

## When to trigger

**Every time the developer profile writes or updates a `docs/*.md` file** in any `~/www/<project>/` directory:

1. Write the MD file.
2. **Run the build script** to produce both engineering + boss HTMLs.
3. If `docs/_meta/<doc>.json` doesn't exist, **ask the agent loop to generate one** (read the MD → call LLM → write JSON to `docs/_meta/<doc>.json`). Or open a kanban task for the CEO worker.
4. **Re-run the build script** so the boss HTML now renders with real cards/decisions/risks.
5. **Do NOT** send a Discord notification (David opens HTML manually via `file://`).
6. **Do NOT** commit the HTML or meta JSON to git.

## How to use

### After writing a project doc

```bash
bash ~/.hermes/profiles/developer/skills/doc-html-preview/scripts/build.sh \
  --project <project-name>
```

This produces:
- `docs/_html/<doc>.html` (engineering)
- `docs/_html/<doc>-boss.html` (boss; renders placeholder if no JSON yet)

### Generating the boss summary JSON

The `docs/_meta/<doc>.json` is generated by an LLM reading the MD. Use the developer profile's `CEO` subagent (per SOUL.md subagent matrix) or call directly:

```python
# Pseudocode
md_text = open("docs/PRD.md").read()
prompt = f"""
You are the CTO of a software team. Read this PRD and produce a JSON
summary for the boss to make decisions. Output exactly this schema:

{{
  "doc": "PRD",
  "source_md": "docs/PRD.md",
  "generated_at": "<ISO timestamp>",
  "generated_by": "AI (developer profile / CEO subagent)",
  "one_liner": "<ONE sentence, non-technical, what is this for>",
  "cards": {{
    "timeline": "<short estimate>",
    "cost": "<short estimate>",
    "mitigation": "<what's already planned to de-risk>",
    "disclaimer": "<one-line warning that estimates are preliminary>"
  }},
  "decisions": [
    {{ "question": "...", "options": [
        {{"label": "A. ...", "pros": "...", "cons": "..."}},
        {{"label": "B. ...", "pros": "...", "cons": "..."}}
      ], "default": "A", "blocking": true
    }}
  ],
  "risks_boss_speak": [
    "<risk 1 in plain language>",
    "<risk 2 in plain language>"
  ]
}}

PRD:
{md_text}
"""
# Call LLM, parse JSON, write to docs/_meta/PRD.json
```

Then re-run the build script.

### MD override (escape hatch)

If you want a manual boss version (skipping AI generation), add this section to the MD:

```markdown
## 👀 老闆版摘要

呢個 PRD 嘅重點係 blah blah...

主要拍板事項：
- 揀 A 定 B?
- 揀 X 定 Y?
```

The build script will:
- Use the content under this heading as the boss body (replacing AI cards/decisions/risks)
- Use the first `<p>` paragraph as the one-liner in the top blue callout

This is for when David wants full control over what he sees, and doesn't want AI-generated content for sensitive decisions.
