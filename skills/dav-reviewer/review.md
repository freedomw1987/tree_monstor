# Dav Reviewer — 審核流程（Gate 4）

> 本檔為 `dav-reviewer` skill 嘅「Gate 4 品質審核」流程子檔；主檔只留指標。
> 需求對帳（Gate 4.5）嘅流程 → 同套 `./workflow.md`；兩道 Gate 嘅定義 → 同套 `./gates.md`。

## §1 核心角色 ＋ Gate 4 前置

- **dev** — 職責：領取任務 → 依 DESIGN.md／system-design.md／PRD 開發 → 保留探針 → 標記「等待校驗」
- **checker** — 職責：監控 backlog → 發現「等待校驗」→ 全面校驗 → 問題記錄 → dev 自動修復
- **前置**：Gate 1 測試已紅、Gate 2 已綠、Gate 3 探針已埋好（否則 reviewer 會捉到「測試係假綠」）
- **角色分工 ＋ 證據**：dev 做實作 → checker subagent 做獨立校驗 → 有問題返 dev 修 → 重複；checker 原文回傳（唔准自己改寫成「已通過」）
- **人手觸發**：Gate 4 唔喺執行段（自動段）內 → 由用戶叫先做；做就要做齊（唔准「意思意思」）

## §2 Checker 工作流程

- **1 監控 Backlog** — 持續讀 `docs/backlog.md` → 篩選「等待校驗」→ 如有新任務則開始校驗
- **2 全面校驗** — 功能正確性（對照 PRD）｜代碼品質（風格／安全性／可讀性）｜測試覆蓋｜Regression 探針是否正確運行
- **3 記錄問題** — 在 backlog 新增 Defect 條目 → 原任務狀態改為「需修復」→ 循環次數遞增
- **4 通過驗收** — 所有檢查通過 → 狀態改為「已完成」→ 記錄完成時間

## §4 循環終止條件 ＋ 循環控制

- **用戶手動終止** — 由用戶決定何時停止；**所有任務完成** — backlog 為空且所有狀態為「已完成」
- **循環上限** — 任一問題超過 20 次循環仍未解決則中斷（**0** = 問題剛被記錄／**1-19** = 正常修復循環／**20** = 達到上限）
- **達到 20 時**：在 backlog 標記「達到循環上限」→ 通知用戶需人工介入 → 停止自動修復（該問題不再自動處理）

## §5 協作默契

- **Dev 不干擾 Dev** — 同一時間只有一個 dev 處理同一任務；**Checker 客觀公正** — 嚴格按照標準檢查，不妥協
- **循環有上限** — 避免無限修復，20 次上限保護；**記錄清晰** — 每個問題都有明確的描述和追蹤

## §3 審核規則（獨立 subagent）

- **獨立 reviewer 必開 subagent** — 例外：環境無 subagent 能力 → 降級並明示；限制：唔准自己審自己
- **UI 任務必跑 playwright-cli E2E**（連截圖證據） — 例外：純後端／CLI／腳本可跳過；限制：要在對話明示「無 UI 故不適用」及理由
- **有問題就返 Step 2 修** — 例外：無；限制：修完要重跑 Gate 3（探針／回歸）
- **證據要原文回傳** — 例外：無；限制：唔准改寫成「已通過」
- **校驗清單範例** → 同 skill 子檔 `./examples/reviewer-checklist.md`（Module 級校驗清單範本，可直接抄）

## §4 同需求對帳（Gate 4.5）嘅關係

- 同一次 review pass 內完成：品質審核（Gate 4）＋ 需求對帳（Gate 4.5）→ 兩份結果一併交返用戶
- 對帳流程（5 步）→ 同套 `./workflow.md`；對帳表格式 → 同套 `./reconcile-format.md`
- 對帳嘅輸入（需求錨點 ＋ 變更清單）刻意做少 → 見 `./workflow.md` Step 1
