# Dav Reviewer — 需求對帳表格式

> 本檔定義「需求對帳表」（Gate 4.5）嘅固定格式與狀態判定準則。入口在同套 SKILL.md。
## 1. 檔案契約

- **路徑**：專案端 `docs/reconcile/<US-ID>-reconcile.md`（`<US-ID>` 與需求錨點檔、AC 範本同名）
- **一個 US 一份**（與專案端 `docs/ac/`、`docs/prd/` 的慣例一致）
- **可覆核**：任何人拿需求錨點 + 變更清單都能重跑並得到同樣的判定依據
## 2. 檔案結構

- **標題行**：`<US-ID> 需求對帳表`
- **檔頭兩行**：對帳者（subagent 名稱）｜ 對帳時間（YYYY-MM-DD）｜ 錨點（`docs/req/<US-ID>-requirement.md`）；下一行係覆蓋率（已列 R-ID 數 / 錨點 R-ID 總數）
- **對帳表段**：一列一個 R-ID，六欄（需求 ID / 需求句（摘要）/ 狀態 / 實作位置 / 證據 / 備註）—— 欄位規則見 §3
- **結論段**：全部已實作 / 有 n 項部分實作 / 有 n 項未實作 ＋ 對帳者備註（一句話；不得替執行者辯護）
- **可複製範本** → 同 skill 子檔 `templates/reconcile-table.md`
  （⚠️ 對帳表**必須**用 markdown 表格：文件漂移檢查 D7 靠 `| R<n> |` 列 + 狀態符號解析，唔可以改成列表）
## 3. 欄位定義

- **需求 ID**｜必填：✅｜規則：錨點的 R-ID；**必須覆蓋全部 R-ID**，不得只列「有問題的」
- **需求句（摘要）**｜必填：✅｜規則：一句話；**不得改寫需求含意**（要引用原話時放引號）
- **狀態**｜必填：✅｜規則：僅 4 種值（見 §4）
- **實作位置**｜必填：✅｜規則：具體到檔案（可加行號 / 函式名）；**不得只寫「已完成」**；未實作則填 —
- **證據**｜必填：✅｜規則：已實作必填（測試名 / 執行指令 / 探針編號）；未實作填 —
- **備註**｜必填：選填｜規則：說明缺什麼 / 為什麼沒做 / 有無替代做法
## 4. 狀態值（4 種，不得自創第 5 種）

- **✅ 已實作**｜判定準則：需求句的**全部條件**都能在變更清單裡找到對應實作，且有可驗證的證據
- **⚠️ 部分實作**｜判定準則：有實作但**缺部分條件**（例如只做了 happy path、漏了錯誤處理、只改了後端沒改文件）
- **❌ 未實作**｜判定準則：找不到對應實作
- **🚫 已作廢**｜判定準則：該需求句已被取消（規劃階段標註「已作廢」）→ **不列入交付狀態判定**，但**必須列出**（不可省略）

**常見誤判（要避免）**：

- **「檔案有提到相關字樣就算已實作」**｜為什麼錯：提到 ≠ 實作；要能指出實作位置與行為
- **「改了很多檔案所以算已實作」**｜為什麼錯：數量不是覆蓋率；要看 R-ID 逐條
- **「需求被理解成比較大的範圍，所以部分也算已實作」**｜為什麼錯：縮小需求必須由用戶同意，不能由對帳者自行放寬
- **「測試沒有但功能做了，算部分實作」**｜為什麼錯：沒有可驗證證據 → 至少 ⚠️，並在備註點名
## 5. 完整性規則

- **覆蓋率 100%**｜說明：錨點有 n 條 R-ID → 表內必須有 n 列（**含已作廢者**；作廢只是不列入門檻判定，不是可以省略）
- **漏列視為未對帳**｜說明：沒提到 ≠ 已實作；漏列的 R-ID 等同 ❌ 未實作
- **錨點無需求句**｜說明：錨點存在但 R-ID 數 = 0 → **對帳失敗**（不得視為「無需對帳」）
- **作廢需求句**｜說明：錨點「澄清後驗收句」標註已作廢者 → 對帳狀態記 🚫 已作廢，**不阻擋交付狀態**（否則取消需求就永遠交付不了）
- **降級標註**｜說明：非獨立 subagent 執行時，檔頭與結論都要標「對帳降級（無獨立 subagent）」
## 6. 對帳者拿到的輸入（刻意做少）

- **只俾**：需求錨點檔全文 ＋ 最終變更清單（檔案 + diff）；**唔俾**：執行者嘅完成宣告／過程自述（會帶偏對帳者）
- 完整理由同交接口徑 → 同套 `./workflow.md` Step 1
## 7. 交付狀態對應（硬門檻）

- **全部 ✅ 已實作（🚫 已作廢不計入）**｜交付摘要允許的狀態：可標「✅ 完成」
- **任一 ⚠️ 或 ❌**｜交付摘要允許的狀態：**不得**標「✅ 完成」；只能標「⚠️ 部分完成」+ 待補清單
- **全部 ❌ 未實作**｜交付摘要允許的狀態：可標「❌ 未完成」
- **對帳缺失 / R-ID 未覆蓋 / 降級未標註**｜交付摘要允許的狀態：**不得**標「✅ 完成」
