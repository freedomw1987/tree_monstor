# Dav Reviewer — 需求對帳流程（Gate 4.5，5 步）

> 本檔為 `dav-reviewer` skill 嘅「Gate 4.5 需求對帳」流程子檔，逐 Step 寫「動作 / 為什麼 / 產出 / 證據」。
> 品質審核（Gate 4）嘅流程 → 同套 `./review.md`；兩道 Gate 嘅定義 → 同套 `./gates.md`。

## Step 1：準備輸入（刻意做少）

- **動作**：組出對帳者要拿的東西 —（a）需求錨點檔全文（`docs/req/<US-ID>-requirement.md`）（b）最終變更清單（檔案 + diff）（c）該 US 既有文件（AC 範本、backlog 該列）
- **為什麼不給更多**：執行者的完成宣告與過程自述會把對帳者帶向「照著我說的寫」；對帳的價值在獨立比對
- **產出**：一份給對帳者的輸入包（對話內直接給，不落檔）
- **證據**：對話中可見「我給了什麼、沒給什麼」

## Step 2：交給獨立 subagent 對帳

- **動作**：由**未參與本次實作**的 subagent 依同套 `reconcile-format.md` 產出對帳表
- **為什麼**：自己驗自己 = 沒有驗證；獨立性是這個機制唯一的價值來源
- **產出**：對帳表內容（Markdown 表格，格式見 `templates/reconcile-table.md`）
- **證據**：對帳者身分可辨識（subagent 名稱）+ 對話中貼出原文

## Step 3：檢查完整性（R-ID 覆蓋）

- **動作**：確認對帳表**覆蓋錨點的全部 R-ID**，一條都不能漏
- **為什麼**：漏掉的 R-ID 等於沒對帳；「沒提到」不等於「已實作」
- **產出**：完整性檢查結果（覆蓋率 = 已列 R-ID / 錨點 R-ID 總數）
- **證據**：覆蓋率 100% 才算對帳完成

## Step 4：寫檔 + 回報

- **動作**：把對帳表寫進目標專案 `docs/reconcile/<US-ID>-reconcile.md`；回報結論（全部已實作 / 有部分 / 有未實作）
- **產出**：對帳表檔案 + 結論
- **證據**：檔案存在 + 狀態統計

## Step 5：交給交付摘要（狀態降級）

- **動作**：把對帳結論交給交付摘要產出方；對帳有「部分實作／未實作」時，交付狀態**不得**標「完成」
- **為什麼**：對帳不通過還敢標完成 = 這個機制白做
- **產出**：交付摘要的狀態 + 待補清單
- **證據**：交付摘要內含「需求對帳」段
