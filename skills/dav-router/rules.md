# Dav Router — 任務分流 ＋ SOP 防線（規則本體）

> 本檔為 `dav-router` skill 嘅規則子檔；主檔只留指標。內容係 SOP 嘅「一般任務分流」＋「違規回報（防線）」兩段。

## §1 一般任務分流（唔寫 code 唔好走全套）

適用於查資料、生成音樂／圖片／PDF／PPT、單純諮詢、文件潤稿、單次問答等**唔會產生程式碼或修改專案結構**嘅任務。

### 1.1 兩步流程

- **Step 1 溝通 & 思考（輕量版）** — 直接問問題、釐清需求；唔需要 `dav-planner`；一個問題等用戶回答後再問下一個；
  若一句話就得出方案，可以直接跳去執行。
- **Step 2 執行** — 按用戶需要執行合適嘅 skill：用戶明確指定就直接用；冇指定就自己判斷並主動執行
  （例：「生成音樂」→ `minimax-music-gen`、「查最新資訊」→ `web_search`）；都不確定就問一次，唔好反覆確認；
  結束時簡單講解完成咗乜；唔需要交付摘要、唔需要六維度反省、唔寫 backlog。

### 1.2 範例對照

- 「幫我搜尋 XX 資料」→ 直接用 `web_search`，完成後簡單總結
- 「生成一首關於 XX 的歌」→ `minimax-music-gen`，完成後告知結果
- 「幫我把這份 Markdown 轉成 PDF」→ `minimax-pdf`，完成後給檔案路徑
- 「幫我寫一個 React 元件」→ ❌ 開發編程任務 → 交返 `dav-planner`（規劃）起步
- 「我想為我的 App 加一個登入功能」→ ❌ 開發編程任務 → 交返 `dav-planner`（規劃）起步

### 1.3 🚨 自動升級為開發編程任務（強制條款）

執行一般任務時，若發現以下任一情況，**必須立即停下 ＋ 在對話明示「⚠️ 任務升級」**，等用戶確認後交返規劃流程重走：

- **需要新增／修改程式碼** — 例：「順便幫我把這個邏輯寫成函式」
- **需要建立專案結構或 `docs/backlog.md`** — 例：「先列個 backlog 我看一下」
- **任務範圍擴大、需拆分成子任務** — 例：「這個功能還要包含 XX、YY、ZZ」
- **用戶對品質要求上升到「要可維護」「要測試」** — 例：「這個以後要長期維護，要寫測試」

> **例外：trust mode 進行中，上表升級觸發器唔套用。** 升級嘅定義係「停下問用戶確認」，而 trust 嘅紀律係
> 「中途不問用戶」→ 兩者直接互斥。trust 內需升級時：① 寫進 trust-log（可推翻標記）；② 必要時寫進
> need-you-help 檔，交由用戶喺 trust 結束後逐題回覆。

### 1.4 違規處理

- ❌ Agent 喺一般任務中偷偷寫 code → 視為 SOP 違規
- ❌ Agent 跳過升級確認直接做 → 視為 SOP 違規
- ✅ Agent 停下 ＋ 明示「任務升級」＋ 等用戶確認 = 合規

## §2 SOP 違規回報與處理（防線機制）

> 目的：確保 SOP 唔會被 Agent 跳過／假裝通過；用戶有明確機制處理違規情況。

### 2.1 🚨 Agent 必須做的事（自我違規檢查）

- **發現自己跳過咗某個 gate** → 立刻停下，在對話明示「⚠️ SOP 違規：跳過了 Gate X」＋ 解釋點解 ＋ 補做
- **發現自己假報通過 gate** → 立刻停下，在對話明示「⚠️ SOP 假報：Gate X 實際未通過」＋ 重新跑 gate
- **發現任務應該升級但自己冇停** → 立刻停下，在對話明示「⚠️ 任務應該升級但跳過了」＋ 交返規劃流程
  （trust mode 進行中：改記 trust-log ＋ need-you-help 檔）
- **發現 reviewer subagent 報錯仍繼續推進** → 立刻停下，回到 Gate 4 重做

### 2.2 🚨 用戶必須做的事（發現 Agent 違規時）

- **Agent 跳過 gate 卻聲稱完成** → 用戶立刻中斷 Agent，回報「你跳過了 Gate X，請補做」
- **Agent 假報 gate 通過** → 用戶立刻中斷 Agent，回報「Gate X 沒真實通過，請給我看證據」
- **Agent 沒停下來升級任務** → 用戶立刻中斷 Agent，回報「這應該走規劃 → 設計 → 執行，請停下」
- **Agent 重複違規（≥3 次）** → 嚴重警告，必要時結束對話、重置 session

### 2.3 📋 違規記錄

- Agent 每次發現違規都要喺對話中記錄（含時間、違規 gate、處理方式）
- Sprint／Module 級別反省時，把違規記錄納入 6 維度檢查嘅「可維護性」維度

### 2.4 關鍵心法

> 「SOP 是給 Agent 用的安全帶，但安全帶要有人扣上才有用。」
> 用戶是「最後一道安全閥」—— Agent 不主動扣時，用戶要主動提醒。
