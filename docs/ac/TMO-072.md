# TMO-072 需求對帳機制（新 skill dav-reconciler）

> 對應 Backlog: TMO-072
> 最後更新: 2026-10-26
> 狀態: done (2026-10-26)

## 背景

使用者回報的核心問題：「用戶提出需求，到最後 AI 出來的成果對不上」。目前流程裡，交付摘要是由執行任務的同一個 Agent 自我敘述，等於自己評自己，沒有任何第三方比對「原始需求 ↔ 最終成果」。本 US 引入獨立對帳：未參與實作的
subagent 拿需求錨點與最終變更清單做比對，並以硬門檻擋下未對上的成果。

## Given / When / Then

### AC01

- **Given** 一個 US 已完成實作
  **When** 進入 §2.4 反省之前
  **Then** 由**未參與實作的獨立 subagent** 產出「需求對帳表」
  **And** 對帳輸入＝需求錨點（docs/req/）+ 最終變更清單
  **And** 對帳輸出逐條覆蓋每一句需求

### AC02

- **Given** 對帳表有「未實作」或「偏離」項
  **When** 產出交付摘要
  **Then** 狀態**不得**標「✅ 完成」
  **And** 只能標「⚠️ 部分完成」並列出待補項

### AC03

- **Given** 對帳表逐條對上
  **When** 產出交付摘要
  **Then** 可標「✅ 完成」
  **And** deliverable 含「需求對帳」段（需求句 → 實作位置 → 狀態）

### AC04

- **Given** 本次工作修改了 SOP 檔（gates.json / handbook / skill / AGENTS.md）
  **When** 收工
  **Then** 依 V03 走 Reviewer 二審並附風險分級
  **And** 二審結論寫進 changelog

## 風險

- 「未參與實作」的 subagent 在單 agent 環境不可得 → 需退化成自我對帳並在 deliverable 標明降級
- 對帳品質取決於 subagent 給的上下文（需明確告知：只看錨點 + diff，不看實作過程的自述）
- 硬門檻會讓過去標「✅ 完成」的任務重新被標「⚠️」→ 屬預期收緊，非迴歸
