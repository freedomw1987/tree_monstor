# TMO-082 Context 瘦身刀 ＋ 框架體重守門（A+D）

> 對應 Backlog: TMO-082
> 最後更新: 2026-10-26
> 狀態: done (2026-10-26)

## 背景

TMO-075（第一刀）砍咗框架嘅 meta 自我管理層，但**高頻成本未處理**：agent 每次觸發 skill 都要讀
`SKILL.md` ＋ 被點名嘅支援檔。動工前實測（口徑：13 個 skill 嘅 `SKILL.md` ＋ 所有支援 `.md`，git tracked）：

| 量度 | 動工前 | 動工後 | 變化 |
| --- | --- | --- | --- |
| context 總量（SKILL.md + 支援 .md，唔含 CHANGELOG） | 9,619 行 | **7,413 行** | **−2,207（−22.9%）** |
| regression-guard | 2,495 | 1,623 | −872（−35%） |
| dav-wiki | 1,354 | 765 | −612（−45%） |
| tdd-test-writer | 699 | 387 | −312（−45%） |
| dav-trust | 1,186 | 962 | −224（−19%） |
| 框架／產品行數比 | 3.0063 | **2.9203** | −0.090（−3.0%） |

本票做兩件事：**A** = 壓縮支援檔（context 瘦身）；**D** = 加可量度嘅守門防回潮。

## Given / When / Then

### AC01

- **Given** repo 內每個 skill 嘅 `SKILL.md` ＋ 支援 `.md`
  **When** 跑 `python3 scripts/ci/check-framework-weight.py`
  **Then** 印出每個 skill 嘅 context 成本、框架／產品行數比、產物線檔案數（儀表板）

### AC02

- **Given** 動工前 context 總量 9,619 行（SKILL.md + 支援 .md，唔含 CHANGELOG；口徑見背景）
  **When** 完成 A 刀
  **Then** context 總量 ≤ 7,900 行（實際 7,413，−22.9%）且**零被探針錨定嘅內容契約損失**

### AC03

- **Given** 支援檔被壓縮
  **When** 跑全量 `bats tests/`
  **Then** 全部探針綠（被錨定嘅字串／段落結構／檔案存在性一個唔少）

### AC04

- **Given** 有人日後令某個 skill 嘅支援檔膨脹、令 SKILL.md 指向唔存在或被掏空嘅子檔
  **When** 跑守門腳本
  **Then** rc≠0，並指名邊個 skill、邊個檔、超咗幾多行（fail-closed，唔准「掃唔到就當綠」）

### AC05

- **Given** 框架層（tests+docs+scripts+lib+ci+install.sh）膨脹令框架／產品比明顯上升
  **When** 跑守門腳本
  **Then** rc≠0（ratchet：baseline + tolerance；正常加探針唔會誤紅）

### AC06

- **Given** 守門腳本本身
  **When** 跑 `tests/framework-weight.bats`
  **Then** 每支壞情境（超預算／死指標／子檔掏空／枚舉壞／ratio 超標／冇 skills 目錄／裸名引用嘅子檔被掏空或刪除／支援檔之間嘅死指標／cap 被設成 0／產品層 0 行）都有實測證明會紅，
  且 CI 已接上、不得 `|| true` / `continue-on-error`

### AC07

- **Given** 本票改咗 `skills/` 同 `tests/`（規格層）
  **When** 交付
  **Then** 已經獨立 Reviewer subagent 二審（附風險分級 ＋ 跨 SOP 一致性檢查），結論隨交付摘要一併呈現

## 風險

- **壓縮支援檔可能剪走「格式契約」**（例如輸出範例、frontmatter 欄位清單）→ 已用「被探針錨定嘅內容契約清單」逐項守住，
  並靠全量探針回歸；探針冇錨到嘅（純教學式長文）才刪。
- **context 用行數做代理**（token 數更準，但行數可審核、可 diff）→ 已知邊界，寫在設定檔。
- **框架／產品比會被加探針推高** → 所以用 baseline + tolerance 嘅 ratchet，而唔係硬上限。
- **設定檔本身可以被放寬**（cap / baseline 改大就冇人守）→ cap 改動 = 規範改動，須走 V03；FW-1 鎖住必要欄位存在。
