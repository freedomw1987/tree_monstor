## 背景

TMO-082（第二刀）之後，用戶問「還有什麼可以減磅」。量測後提出 6 個候選，用戶揀 **A**：
①**context 層二輪瘦身** ②**產物線存量清理**（並要求先講方法、批准後先做）。

## Given / When / Then

### AC01

- **Given** 用戶問「仲有咩可以減」
  **When** 量度現況並逐塊評估
  **Then** 每個候選都標明**可減量 × 風險 × 實際障礙**（引用鏈檢查結果），且第一個方案標明最推薦及理由

### AC02

- **Given** 用戶選咗 A 方案但要求「先不要做住」
  **When** 交付計劃（逐檔剪邊段／留邊段／目標行數 ＋ 5 步安全網 ＋ 4 批執行順序 ＋ 引用鏈查法）
  **Then** **喺得到批准前唔改任何檔案**；批准後按計劃執行

### AC03

- **Given** 9 支支援檔（分佈喺 8 個 skill）
  **When** 執行 context 二輪瘦身（去重／表格化／指標化／骨架共用）
  **Then** context 總量下降，且**被探針錨定嘅內容契約一個唔少**（含 dav-wiki FR-3 多模組例）

### AC04

- **Given** 存量產物（3 支歷史交付摘要 ＋ 7 支存量 `docs/ac/*.html`）
  **When** 先查引用鏈（探針 fixture／D4 存在性檢查／純文字歷史），再按引用類型處理
  **Then** 零依賴者直接刪；有 D4 引用者加**附理由**的白名單；刪除後 doc-drift D1..D8 仍然全綠

### AC05

- **Given** 本票改咗 skill 子檔、探針註解、docs 契約層
  **When** 交付
  **Then** 已經獨立 Reviewer subagent 二審（風險分級 ＋ 跨 SOP 一致性檢查），結論隨交付摘要呈現

### AC06

- **Given** 瘦身前後嘅量測
  **When** 全部檔案落盤（`git add -A`）後重測
  **Then** context 總量同框架／產品比同步下降，且**守門 rc=0**（新 baseline 已按落檔後實測值設定）
