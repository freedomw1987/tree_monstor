TMO-071 文件漂移探針（8 類字面對帳 D1..D8）

對應 Backlog: TMO-071 | 最後更新: 2026-10-26 | 狀態: done (2026-10-26)

背景

實例：`docs/ac/US-M71.md` 狀態仍是 PENDING，但它對應的 TMO-021 在 backlog 已是 done —— 同一件事兩份文件各說各話。這類「字面層漂移」不需要 AI 判斷，可以用機械化探針抓住，成本低、可進 CI、能擋退化。本 US 做 8 類字面對帳。

Given / When / Then

AC01
Given 任一專案的 `docs/ac/*.md` 與 `docs/backlog.md`
When 跑 `scripts/ci/check-doc-drift.sh`
Then 檢查 8 類：①AC 範本狀態 vs backlog 狀態 ②AC 編號連續且唯一（AC01..ACn） ③PRD 追溯矩陣 ID ⊆ backlog ID ④deliverable 提到的檔案真的存在 ⑤`ac/*.md` 與 `ac/*.html` 狀態一致 ⑥AC 範本 ↔ 需求錨點對應關係
AC02
Given 存量專案有已知不一致項
When 跑檢查
Then 該項被白名單豁免且**輸出說明為豁免**（不得靜默跳過）
AC03
Given 有人把 AC 範本狀態改成 done 但 backlog 沒改
When 跑檢查
Then rc≠0 且指出是哪一筆 ID（抓得到）
AC04
Given 探針本身被破壞
When 跑突變測試
Then 對應探針必須變紅（證明不是假綠）
AC05
Given CI workflow
When 檢視 yaml
Then 有一個步驟真的呼叫該檢查腳本
And 不得 `continue-on-error` / `|| true`

DoD

  • ☐ AC01 / AC02 / AC03 / AC04 / AC05 全綠
  • ☐ `scripts/ci/check-doc-drift.sh` 可攜（`--root` 指向目標專案）
  • ☐ `tests/doc-drift.bats` 探針含突變測試
  • ☐ 白名單檔 `docs/ci/drift-whitelist.txt`（每行含理由）
  • ☐ CI workflow 加步驟且不得假綠
  • ☐ backlog 標 TMO-071 done

風險

  • AC 摘要 vs 標題「同字」比對可能對格式變動過敏 → 比對前先正規化空白與標點
  • 追溯矩陣 ID ⊆ backlog 只保證「不引用幽靈 ID」，抓不到「漏引用」
  • deliverable 檔案存在性檢查對相對路徑書寫方式敏感 → 需明確路徑解析規則
