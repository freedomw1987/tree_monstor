# TMO-086 dav-planner 加「業務邏輯與依賴」提問維度

> 對應 Backlog: TMO-086
> 最後更新: 2026-10-27
> 狀態: done (2026-10-27)

## 背景

用戶 2026-10-27 指示：`dav-planner` 加一個提問維度「業務邏輯及依賴」。
同時（依 `dav-skill-creater` v2.3 M-Step 2「修改同時必清規範偏差」）修埋讀舊版時發現嘅偏差：
§3 名叫「7 個維度」但實際列咗 9 條（核心 4 ＋ 補充 5），而且個「7」散落 4 處。

## Given / When / Then

### AC01

- **Given** `skills/dav-planner/reference.md` §3 維度展開
  **When** 讀補充維度清單
  **Then** 有第 6 條「**業務邏輯與依賴**」，並且寫清三件事：
  ① **何時必問**（有計算/規則、依賴其他模組或外部系統、US 之間有先後次序）
  ② **點樣問**（V01 一題一輪、2-4 選項、⭐ 推薦第一；建議最後問）
  ③ **答案寫落邊**（業務規則 → AC 條款 ＋ Backlog 詳細段「業務規則」行；依賴 → Backlog「依賴」欄 ＋ 詳細段「依賴」行）

### AC02

- **Given** `skills/dav-planner/SKILL.md` 同 `reference.md`
  **When** 搵「7 個維度」呢個名
  **Then** 全部改成「維度展開（核心 4 維度 ＋ 補充維度）」，**唔再寫總數**
  （加維度唔應該再要改 4 處名稱；成熟度「涵蓋率」亦改成按「觸發咗嘅補充維度」計）

### AC03

- **Given** `skills/dav-planner/backlog-rules.md` 嘅 AC 詳細段範本
  **When** 睇範本
  **Then** 有「**業務規則**」一行（有計算/狀態/權限/冪等規則時必填，冇寫 N/A），
  並寫明「依賴」欄同「業務規則」行嘅來源係 §3 該維度；`examples/backlog.md` 範例同步示範

## 風險

- **多問一輪 = 用戶負擔增加** → 放「補充維度」而非核心，並寫死觸發條件（唔係核心 4 就唔問）
- **問完冇落點 = 答案流失喺對話** → AC01 ③ ＋ Backlog 範本新增欄位雙重保險
- **名實不符（7 vs 9）** 會令 agent 誤判要問幾多 → 改成唔寫總數，從根上消除
