# TMO-087 dav-planner 產出專案術語表 ＋ 跨階段一致用語

> 對應 Backlog: TMO-087
> 最後更新: 2026-10-27
> 狀態: done (2026-10-27)

## 背景

用戶 2026-10-27 指示：`dav-planner` 收集完用戶需求後，整理出一份**專案層** `glossary_list.md`
（A-Z 排序、領域專屬、簡潔定義、獨立頁），目的係**各階段同用戶用同一套詞語** ——
減少理解落差，亦令 LLM 唔使每個階段重新對齊用語。

## Given / When / Then

### AC01

- **Given** `dav-planner` 收集完用戶需求（Step 3 維度展開之後）
  **When** 專案有 **≥ 3 條專屬術語**
  **Then** 產出專案層 `docs/glossary_list.md`，內容符合用戶列嘅 4 個特性：
  ① **A-Z 排序**（英文大寫唔敏感；中文按拼音）② **領域／專案專屬**（唔收通用詞）
  ③ **簡潔定義**（每條一句、≤ 40 字）④ **獨立頁**（唔塞入 SKILL.md，避免每個 skill 觸發都帶成本）

### AC02

- **Given** 術語表規格寫喺 `dav-planner/backlog-rules.md`
  **When** 睇 §4.9
  **Then** 有：產出條件（≥3 條先產、唔為齊全開空檔）、收錄標準（收／不收對照表）、
  格式範本（A-Z 表格：術語／定義／別名）、排序規則、維護規則（其他階段可加、A-Z 插入、改名要同步）

### AC03

- **Given** `dav-planner` 主檔
  **When** 睇流程
  **Then** 有 **Step 3.5：產出術語表**（動作／為什麼／產出／證據／參考），位置喺維度展開之後、寫 Backlog 之前
  → 咁 Backlog / AC 天生用同一套術語；TL;DR 必產出物同規則表同步

### AC04

- **Given** 之後嘅各階段（設計 / 執行 / 驗收 / 交付）
  **When** 專案層有 `docs/glossary_list.md`
  **Then** `dav-designer`／`dev-checker-loop`／`dav-submitter` 各自嘅規則表有一條「術語一致」規則
  → 一律用入面嘅術語、唔好用同義詞；SOP §2.1 Plan Gate 亦列明術語表係規劃產出物

## 風險

- **術語表變成第二本手冊**（context 負擔）→ 只收專屬術語、每條一句、≥3 條先產、唔為齊全開檔
- **術語表寫完冇人跟**（各階段各講各話）→ 三個使用端各有一條規則 ＋ Plan Gate 列明產出物
- **術語改名令舊文件失效** → 維護規則要求改名要同步引用該詞嘅文件（PRD / AC / 交付摘要）
- **同義詞漂移** → 表格有「別名」欄，統一用「術語」欄；其他階段發現新詞要插入同一張表
