## Given / When / Then

### AC01

- **Given** `docs/backlog.md` 有 88 個已完成 row
  **When** 依新規則更新 backlog
  **Then** backlog **只留未完成**（todo／doing／⏸️）嘅 row；完成嘅 row 移出
  （記錄去交付摘要 ＋ 需求錨點 ＋ git history）；**保留／不保留規範寫入會改 backlog 嘅 skill**：
  `dav-planner/backlog-rules.md` §4.5 ＋ `dav-submitter/SKILL.md` Step 5 ＋ 規則表

### AC02

- **Given** `docs/` 有 4 類歷史產物（ac／req／reconcile／deliverable／prd）共 50+ 份
  **When** 逐類判斷「保留 vs 歸檔」
  **Then** 判斷寫入本票並執行：完成 US 嘅 ac／req／reconcile **一併**歸檔（保持 D1/D6/D7 一致）；
  `docs/prd/`（已完成專案）歸檔；`docs/deliverable/` **只留最近一次交付**（連帶保留其引用鏈，
  因為 D8 硬門檻要求窗內有件可對帳）；SOP／CI／工具／術語表／設計文件／安裝說明 **全部保留**

### AC03

- **Given** PoC 嘅 journey 指向專案層 `docs/ac/US-*.md`（skill 唔自足）
  **When** 搬 fixture
  **Then** 5 個 AC fixture 搬入 `skills/dav-jev-oracle/PoC/fixtures/ac/`（2026-10-28 TMO-092 拆分後路徑）；journey `source:` ＋
  PoC 程式引用 ＋ 探針同步；cache fixture 改名（cache key 含 source 路徑 → 改名即可命中）；
  → skill 喺目標專案都跑得

### AC04

- **Given** 全量閘 4 分 10 秒（90% 係重複驗證）
  **When** 跑 `bash scripts/check-all.sh --changed`
  **Then** 只跑受改動影響嘅 repo 級／skill 級探針 ＋ 只跑目標檔被改過嘅 mutant 列；
  跳過嘅步驟**明講原因**；結果行標明「唔等於全量閘通過」

### AC05

- **Given** 「docs/deliverable/ 只留最近一次」呢個做法
  **When** 睇 skill 規格
  **Then** 規則要**寫入 skill**（唔可以只做一次）：`dav-submitter/retention.md`（新子檔：交付摘要 ＋
  `docs/` 保留 vs 歸檔清單 ＋ 執行次序）＋ `SKILL.md` Step 3 保留策略 ＋ Step 5 ＋ 規則表；
  `dav-planner` §4.5 指標去同一處（單一真相，避免兩份規格漂移）

### AC06

- **Given** 全量閘 4 分鐘（而其中 90% 係重複驗證）
  **When** 開發 loop 與 push 前分別用乜
  **Then** **開發 loop 用 `--changed`**（只驗受改動影響嘅探針 ＋ mutant 列，快 6-10 倍）、
  **push 前跑全量**；呢個分工要寫入 repo 規則（`CONTRIBUTING.md` ＋ handbook §2.3 ＋ 腳本頭註解），
  唔可以只係「習慣」——否則下一次改動又會照跑全量
