## 1. 用途

本章定義 **RSI（Recursive Self-Improvement）機制**的完整 SOP，包含：

- 為什麼需要 RSI
- 兩種模式（觀察 vs 聚合）的分離規則
- 完整流程圖（觀察 → 聚合 → 提案 → **Reviewer 二審** → 用戶審批 → 合併 → 同步）
- 4 條不可違反安全規則
- 安裝與部署指引

## 2. RSI 為何存在

### 2.1 問題

tree_monstor 已部署到多個專案，每個專案執行 SOP 時會遇到：

- 規範模糊 → Agent 卡住
- 規範不一致 → Agent 行為不可預測
- 用戶自己摸索 → 重複勞動

若沒有 RSI，**每個專案都會重複遇到同樣問題**，且「改進」只會在某個專案發生，**其他專案無感**。

### 2.2 解法

RSI 機制：

1. 觀察：每個裝了 tree_monstor 的專案在任務完成時**自動寫結構化觀察**（不動 SOP）
2. 聚合：用戶在**源 repo**打 `/reflect`，把所有專案的觀察聚合
3. 提案：聚合結果變成「候選 diff」
4. 二審：每個 diff 必經 **Reviewer subagent** 二審（V03 紀律）
5. 批准：用戶看到「diff + verdict」並呈後批准
6. 合併：套用 diff + git tag
7. 同步：`rsi-sync.sh` 把改完的 SOP 同步到所有已裝專案

## 3. 兩種模式分離（核心安全原則）

| 模式 | 環境 | 能力 | 觸發點 |
|---|---|---|---|
| **觀察模式**（observation） | 任何裝了 tree_monstor 的專案 | **只寫** observation JSON 到 `~/.tree-monstor/observations/` | 任務完成時自動 |
| **聚合模式**（aggregation） | **源 repo**（`tree_monstor/`） | 收集觀察 + 聚合 + 產出 diff 提案 | 用戶打 `/reflect` |

**為什麼分離**：裝在用戶專案裡的 agent 沒有權限動用戶的 SOP 源頭。改 SOP 只能由用戶**在源 repo**明確觸發。

詳細規範見 [`/skill:sop-evolver`](../../../.agents/skills/sop-evolver/SKILL.md)。

## 4. 完整流程圖

```
┌─────────────────────────────────────────────────────────────┐
│  RSI 完整流程：觀察 → 聚合 → 提案 → 二審 → 批准 → 合併 → 同步  │
└─────────────────────────────────────────────────────────────┘

[任何裝了 tree_monstor 的專案]
   ↓ 任務完成
[Gate 5 觸發] → sop-evolver skill（觀察模式）
   ↓ 寫 ~/.tree-monstor/observations/{project-id}/{YYYY-MM-DD}.json
   ↓ （觀察失敗不阻塞任務，observability 不在 critical path）
   ↓
[用戶 cd 回源 repo + 打 /reflect]
   ↓
[Gate 5] → sop-evolver skill（聚合模式）
   ↓ 收集所有專案的 observation
   ↓ 去重、排序、統計
   ↓ 產出 docs/sop/rsi-aggregated-{YYYY-MM-DD}.md
   ↓
[/propose] → rsi-propose.sh
   ↓ 讀聚合報告
   ↓ 對每個 Top N 信號產生「候選提案骨架」
   ↓ 寫 docs/sop/rsi-proposals/{date}-{NN}.md
   ↓ （不直接生成 diff，避免 agent 自動修改）
   ↓
[Reviewer 二審] ⚠️ V03 紀律（必經）
   ↓ dev-checker-loop (Reviewer subagent)
   ↓ 風險分級 🟢/🟡/🔴 + 跨 SOP 一致性檢查 + 修改建議
   ↓ 寫 docs/sop/rsi-reviewer-verdict-{date}.md
   ↓
[用戶審批]
   ↓ 用戶看到「diff + verdict」兩者並呈
   ↓ 用戶批准 / 退回 / 要求改架構
   ↓ （可明確說「跳過 Reviewer」明示豁免）
   ↓
[套用 diff + git tag rsi-v{YYYYMMDD}-{NN}]
   ↓
[更新 docs/sop/rsi-log.md]
   ↓
[Gate 5 通過] 任務完成
   ↓
[rsi-sync.sh] → 同步 SOP 到所有已裝專案
   ↓ 透過 symlink + rsi-overlay.sh
   ↓ 不覆蓋用戶本地 override（sync 規則見 §6.3）
   ↓
[觀察下一個任務 → 循環改進]
```

## 5. 觀察記錄存放位置

```
~/.tree-monstor/observations/{project-id}/{YYYY-MM-DD}.json
```

- `project-id` = `SHA256(安裝路徑).substring(0,8)`（**絕不存明文路徑**）
- 每個 task 寫一個 JSON 檔
- 觀察失敗**不阻塞**任務（log warning，跳過寫入）

### 5.1 觀察 JSON Schema（白名單 + 黑名單雙重保護）

**白名單欄位**（多餘欄位 → ajv reject）：

| 欄位 | 型別 | 說明 |
|---|---|---|
| `task_id` | UUID | 任務 ID |
| `project_id` | string | `SHA256(path).substring(0,8)` |
| `timestamp` | ISO-8601 | 觀察時間 |
| `gate_results` | object | 5 Gate 的 pass/fail（Gate 1-5，含 Gate 5 RSI gate） |
| `skills_used` | array | 使用的 skill 名 |
| `failure_signals` | array | 失敗信號 `{gate, type, count}` |
| `duration_seconds` | integer | 任務耗時 |

**黑名單欄位**（被拒絕）：

- ❌ `raw_conversation`（raw 對話內容）
- ❌ `code_snippets`（程式碼片段）
- ❌ `file_paths`（檔案絕對路徑明文）
- ❌ `env_values`（環境變數值）
- ❌ `git_messages`（git commit message 內容）

詳見 [`/skill:sop-evolver/observation.md`](../../../.agents/skills/sop-evolver/observation.md)。

## 6. 4 條不可違反安全規則

### 6.1 規則 1：觀察/改動分離

| 允許 | 禁止 |
|---|---|
| 任何裝了 tree_monstor 的專案都**可寫** observation | 任何裝了 tree_monstor 的專案都**不可改** SOP/AGENTS.md/gates.json/handbook/skill |

### 6.2 規則 2：匿名化

| 允許 | 禁止 |
|---|---|
| 存 `project_id` = `SHA256(path)[:8]` | 存**明文路徑**、**明文專案名**、**明文程式碼** |
| 存結構化信號（gate 結果、失敗類型、頻率） | 存 **raw text**、**絕對路徑**、**環境變數值** |

### 6.3 規則 3：Reviewer 二審必經

所有 SOP / AGENTS.md / gates.json / handbook / skill 修改提案：

1. **必先經** `dev-checker-loop` Reviewer subagent 二審
2. Reviewer 必附風險分級（🟢/🟡/🔴）+ 跨 SOP 一致性檢查 + 修改建議
3. 用戶收到「diff + verdict」兩者並呈
4. 用戶可**明確說「跳過 Reviewer」**直接批准（明示豁免）

### 6.4 規則 4：一鍵回滾

每次合併 diff 必自動寫 git tag：

```
rsi-v{YYYYMMDD}-{NN}
```

回滾指令：

```bash
./tools/rsi-rollback.sh rsi-v{YYYYMMDD}-{NN}
```

**特性**：回滾時間 < 5 秒（純 git checkout），觀察記錄**不刪**。

## 7. 安裝與部署

### 7.1 安裝旗標

```bash
./install.sh --enable-rsi   # 預設：部署 sop-evolver skill + 建觀察目錄
./install.sh --disable-rsi  # 不部署 sop-evolver，移除觀察目錄
./install.sh --uninstall    # 完全清理
```

### 7.2 觀察目錄建立

```bash
mkdir -p ~/.tree-monstor/observations/
```

### 7.3 驗證安裝

```bash
# 確認 skill 已部署
ls ~/.pi/sop/skills/sop-evolver/SKILL.md  # 或對應安裝路徑

# 確認觀察目錄可寫
echo '{"test": true}' > ~/.tree-monstor/observations/test.json
rm ~/.tree-monstor/observations/test.json
```

## 8. 故障排除

### 8.1 觀察記錄沒寫

| 可能原因 | 檢查 |
|---|---|
| observation schema 驗證失敗 | 看 `~/.tree-monstor/logs/observation-{date}.log` |
| 觀察目錄不存在 | `mkdir -p ~/.tree-monstor/observations/` |
| 寫入權限不足 | `chmod 700 ~/.tree-monstor/observations/` |

### 8.2 聚合報告空

| 可能原因 | 檢查 |
|---|---|
| 沒觀察資料 | `ls ~/.tree-monstor/observations/`，確認有 JSON 檔 |
| 觀察時間範圍不對 | 預設聚合最近 30 天，可在 `rsi-aggregate.sh` 改 `--days` |

### 8.3 Reviewer 二審失敗（🔴）

| 處理 | 動作 |
|---|---|
| 提案標記「不可合併」 | 等待用戶決定 |
| 用戶退回 | 提案保留 7 天後封存到 `_archive/` |
| 修改提案 | 重新跑 `/propose` + Reviewer |

## 9. 量化指標（rsi-metrics.sh）

| 指標 | 期望值 | 紅線 |
|---|---|---|
| 觀察失敗率（schema reject） | < 5% | > 20% |
| 違規事件數（incident log） | 0 | > 0 |
| Reviewer 跳過率 | < 10% | > 30% |
| 回滾平均時間 | < 10 秒 | > 60 秒 |
| 規範違規次數 | 下降趨勢 | 持續上升 |
| 跨專案觀察分佈 | ≥ 3 個專案 | < 3 個專案 |
