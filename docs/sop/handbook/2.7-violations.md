# §2.7 SOP 違規回報與處理（防線機制）

> 本檔是 SOP §2.7 的詳細內容（AGENTS.md 自 2026-10-26 起不再內嵌 SOP；本節的規則本體以本檔為準）。引用：`[§2.7](./sop/handbook/2.7-violations.md)`

## 目的

確保 SOP 不會被 Agent 跳過 / 假裝通過；用戶有明確機制處理違規情況。

## 🚨 Agent 必須做的事（自我違規檢查）

- **發現自己跳過了某個 gate**
  - Agent 應對：立刻停下，在對話明示「⚠️ SOP 違規：跳過了 Gate X」+ 解釋為什麼 + 補做
- **發現自己假報通過 gate**
  - Agent 應對：立刻停下，在對話明示「⚠️ SOP 假報：Gate X 實際未通過」+ 重新跑 gate
- **發現任務應該升級但自己沒停下**
  - Agent 應對：立刻停下，在對話明示「⚠️ 任務應該升級但跳過了」+ 回到 §2.1（trust mode 進行中：改記 trust-log + need-you-help 檔，不回到 §2.1）
- **發現 reviewer subagent 報錯仍繼續推進**
  - Agent 應對：立刻停下，回到 Gate 4 重做

## 🚨 用戶必須做的事（發現 Agent 違規時）

- **Agent 跳過 gate 卻聲稱完成**
  - 用戶應對：立刻中斷 Agent，回報「你跳過了 Gate X，請補做」
- **Agent 假報 gate 通過**
  - 用戶應對：立刻中斷 Agent，回報「Gate X 沒真實通過，請給我看證據」
- **Agent 沒停下來升級任務**
  - 用戶應對：立刻中斷 Agent，回報「這應該走 §2.1~§2.5，請停下」
- **Agent 重複違規（≥3 次）**
  - 用戶應對：嚴重警告，必要時結束對話、重置 session

## 📋 違規記錄

- Agent 每次發現違規都要在對話中記錄（含時間、違規 gate、處理方式）
- Sprint / Module 級別反省時，把違規記錄納入 6 維度檢查的「可維護性」維度

## 關鍵心法

> 「SOP 是給 Agent 用的安全帶，但安全帶要有人扣上才有用。」
> 用戶是「最後一道安全閥」 — Agent 不主動扣時，用戶要主動提醒。
