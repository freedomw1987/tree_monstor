## 過程檢討

### ✅ 做得好的

1. **V03 SOP 紀律**：SOP 修改必經 Reviewer 二審—已啟動 reviewer subagent，避免單方面修改 SOP 引入不一致
2. **4 個關鍵決策題依 V01/V02**：每次只問 1 題、第一個選項標推薦、附帶「做了會怎樣」，用戶主動選擇最推薦方案
3. **誠實暫停回報範圍**：在 §2.2 開始前主動告知用戶「這次比預期大很多」，給用戶縮小 MVP / 繼續 / 停下 三選一，符合 §1「誠實溝通」
4. **TDD 嚴格執行**：先寫 9 個探針 → 跑出 8 紅燈 → 實作 SKILL.md / docs/ac/ / changelog → 修正章節標題錯字 → 修正連結路徑 → 9 全綠。每次修正都對應一個 fail
5. **路徑驗證自動化**：寫 Python 腳本驗證所有 markdown 內部連結，捕獲 4 個錯誤路徑（`docs/ac/US-XXX.md` → `../ac/US-XXX.md`、`../backlog.md` → `../../docs/backlog.md` 等），避免 SOP 文件互相指向空檔
6. **hardlink 同步確認**：用 `stat -f "%i"` 確認 SKILL.md 是 hardlink（inode 140466901），改一邊兩邊自動同步（與 v1.4 changelog 慣例一致）
7. **HTML 範本品質**：含 `@media print` 媒體查詢、列印時字體 11pt、避免 cell 內斷頁、checkbox 用 `☐`（列印友好）

### 🎯 學到的事

1. **「兩者並存」方案比「取代」更安全**：方案 A（backlog.md 仍是 single source of truth + docs/ac/ 為配套）比方案 B（全部移到 docs/ac/）風險低、向下相容
2. **「同 turn 生成」是必做**：避免 .md / .html 不同步是最常見的實際問題，SOP §4.6.2 明確要求同 turn 三動作
3. **bats 守護的價值**：v1.7.1 已證明 homebrew bats UTF-8 bug 等環境問題會掩蓋 latent bugs；這次新加的 9 個探針會防止未來有人「覺得新章節太多」而悄悄刪除 §4.3.2 / §4.6
4. **HTML 範本不依賴外部資源**：所有 CSS 內嵌、無外部字體 / JS / 圖片，方便分享給無網路環境的客戶 / 跨公司 PO
