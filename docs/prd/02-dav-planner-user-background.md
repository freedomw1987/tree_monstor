# PRD-02: dav-planner 用戶背景收集機制

**版本**：v1.0
**日期**：2026-09-26
**Backlog**：TMO-007
**SOP 版本**：v1.9

---

## 背景

dav-planner skill 在 §2「提問技巧」與 §3「思考和詢問維度」中，目前**完全沒問過用戶自身的背景**（角色、經驗、技術棧）。導致問題：

1. **Agent 提問的深度無差別** — 對 PM 和開發者都問同一句「你想要什麼效果？」
2. **Agent 不知道哪些維度對用戶有意義** — 給設計師問「目標市場」是浪費；給開發者問「品牌規範」是浪費
3. **利害關係人（PO / 業務 / 設計師）首次使用時，缺乏「破冰」機制** — 直接進需求會讓非技術用戶卻步

## 目標

dav-planner 從 v1.9 起，在每次對話**開始**（在 §3 維度之前），先問 **1 題「用戶角色」**，並依角色**動態選擇下一題追問**。

## 範圍

### In Scope（要做）

1. 新增 §2.7「用戶背景收集」章節，內嵌「角色 → 下一題」對應表
2. 角色選項：PM/PO、開發者、設計師、業務負責人/客戶、其他
3. 依角色追問的題目：PM → 目標用戶/規模；Dev → 技術棧/團隊規模；Designer → 品牌規範/視覺風格；業務 → 目標市場/付款物流
4. bats 守護：§2.7 章節存在 + 角色對應表存在 + 至少有 4 個角色
5. changelog v1.9 條目
6. docs/backlog.md 新增 TMO-007

### Non-goals（不做）

1. **不做持久化**：不寫 docs/user-profile.md 等任何檔（用戶選 A 方案：純對話詢問）
2. **不做 persona 與 user 區分混亂**：原 §3 補充 5 維度的「Persona（邊個用）」不變，仍指產品目標用戶；§2.7 是「用戶自己的角色」
3. **不做自動跳過**：即使是技術用戶也要問（這是低成本的破冰）
4. **不整合到 §2.5 任務升級**：任務升級是 SOP 紀律，§2.7 是溝通破冰，兩者職責不同

## 使用流程

```
Agent 啟動
  ↓
§1 原則檢查（既有）
  ↓
§2 提問技巧（既有 §2.1-§2.6）
  ↓
§2.7 用戶背景收集（v1.9 新增）⭐
  - Agent 問 1 題：「請問你在這個項目中的角色是？」
  - 用戶選 A/B/C/D/E
  - Agent 依對應表問下一題（角色相關）
  ↓
§3 思考和詢問維度（既有）
  - 核心 4：目的/痛點/方案/效果
  - 補充 5：non-goals/替代方案/風險/constraints/persona
  - **這些維度的追問深度，會依 §2.7 的角色動態調整**（PM 不問技術、Dev 不問品牌）
  ↓
§4 Backlog（既有）
```

## 設計細節

### §2.7 角色 → 下一題對應表

| 用戶選 | Agent 下一題 |
|--------|-------------|
| **PM/PO** | 這項目的目標用戶是誰？規模（DAU/MAU）？ |
| **開發者** | 你熟悉的技術棧是？團隊規模？ |
| **設計師** | 有品牌規範/色票/字型嗎？視覺風格偏好？ |
| **業務/客戶** | 目標市場是？付款/物流偏好？ |
| **其他** | 請簡單描述你在這項目的角色 |

**規則**：
- 角色題是「一次問一個問題」（V01）
- 追問題也是「一次一個問題」（V01）
- 角色題必須給 4-5 個具體選項（V02）
- 追問題如果需要選項也走 §2.2 V02（推薦標 ⭐）
- 「其他」選項讓用戶自由表達
- 追問題回答後 → 進入 §3 核心 4 維度

### §2.7.1 何時跳過角色題

極少數情境可不問角色題：
- 用戶已經自我介紹過（對話開頭就寫「我是這專案的 PM...」）
- 對話明顯是後續追問（同 US 連續對話的第 3+ 輪）
- 用戶明確說「直接問需求就好」

跳過時 Agent 必須明示「我跳過角色題」並繼續。

### §2.7.2 與既有 §3「Persona」維度區分

| 項目 | §2.7 用戶角色 | §3 Persona 補充維度 |
|------|-------------|-----------------|
| 對象 | **這次對話的用戶** | **產品的目標用戶** |
| 目的 | 調整提問深度與語言 | 定義產品受眾 |
| 持久化 | 否（純對話）| 是（進 backlog.md US 描述）|
| 選項 | PM/Dev/Designer/業務/其他 | 由用戶描述 |

## 風險與緩解

| 風險 | 緩解 |
|------|------|
| 用戶覺得「為什麼又問一次」（同專案第 N 次對話）| §2.7.1 提供跳過規則 |
| 角色分類不夠細（PM vs 業務難分）| 「其他」選項讓用戶細說 |
| 對應表的追問題太抽象 | 給 2-4 個具體選項（V02）|
| §2.7 與 §3 Persona 混亂 | §2.7.2 明確區分對照表 |
