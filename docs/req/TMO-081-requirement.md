## 背景（非用戶原話；係 TMO-079／080 二審過程嘅實測結論）

### 觸發點

做 TMO-079 時重新量測咗 PNA-4 嘅立論前提，發現**原文寫錯**：

| 原文寫（commit `9c04aaa`） | 實測（bats 1.14.0 ＝ CI pin 嘅版本） |
| --- | --- |
| 「獨立的 `[[ ... ]]` 斷言失敗**不會中止 test body**」 | **會中止** |
| 「bash 3.2 唔中止、bash 5.x 會中止」 | **兩個版本一樣中止** |

證據：`bats 1.14.0` 同 `1.11.1` 嘅 `libexec/bats-core/bats-exec-test` 開頭都係 `set -eET`，而 test body 喺
`{ setup "$@"; "$@"; }` 呢個**唔受 `-e` 忽略**嘅語境入面跑 → 獨立嘅 `[[ ]]` 失敗**會**中止 test body。
實測（`bats --print-output-on-failure`）：T1~T7 全部 `not ok`，`echo reached` 一次都冇印出。

**後果**：PNA-4 唔再係「唯一防止靜默失敗」嘅東西 → 佢而家只剩「風格／診斷品質」嘅價值。
該更正已於 TMO-079 內完成（前提改寫 ＋ 重新定位 ＋ `changelog.md` v2.15 ＋ 歷史交付摘要加 pointer）。
**本票只處理「既然咁，PNA-4 應唔應該繼續存在」呢個問題。**

### 由數據推出嘅三個關鍵事實

1. **PNA-4 唔係「零價值」**：repo **已經在用** `set +e`（3 處）。喺嗰種窗口裡面，裸 `[[ ]]` 嘅失敗
   **真係會被靜默吞掉**（`set +e` 令該窗口內嘅 errexit 失效）→ 呢個係**真·會假綠**嘅場景，
   而唔係假設性嘅未來風險。
2. **但規則嘅「理據」錯咗**：PNA-4 而家守住嘅係「所有裸斷言都要包 fail-fast」呢個**風格**要求，
   而唔係「防止靜默失敗」——因為除咗 `set +e` 窗口，bats 自己已經會中止並印出 `file:line`。
3. **「刪規則」同「還原 181 條改寫」係兩件唔同嘅事**：236 條 fail-fast 改寫**唔會**造成任何損害，
   而且佢哋係診斷訊息嘅來源（`FAIL: <file>:<line>`）。真正嘅「減法」目標如果係診斷品質，
   應該係**收窄規則**，而唔係還原改寫。

### 成本（每個方案嘅改動量同風險）

| 方案 | 改動量 | 保留咗啲乜 | 風險 |
| --- | --- | --- | --- |
| **A** 保留現狀 | 0（前提已於 TMO-079 更正） | 全部 | 繼續維護一條「理據已錯」但無害嘅規則；日後讀者仍可能誤以為佢防假綠 |
| **B** 刪規則，留 236 條改寫 | −177 行掃描器、−3 canary、−3 mutant、文件同步 | 236 條改寫＋診斷訊息 | 風格**冇機械守門** → 日後新探針可能寫裸斷言（bats 仍會中止，但冇 repo 慣例提示） |
| **C** 收窄成「只守 `set +e` 窗口內嘅裸斷言」 | 掃描器加 `set +e` 邊界追蹤；規則④⑤⑥⑦ 大部分可簡化；canary/mutant 重寫 | 真·假綠防護（唯一真實嗰個） | 規則複雜度轉移（要識 `set +e` / `set -e` 配對）；需重做 canary + mutant |
| **D** 全刪＋還原 181 條 | −177 行掃描器 ＋ **約 180 處還原** | 冇 | ⚠️ **唔建議**：會拎走 `FAIL: <file>:<line>` 診斷訊息（bats 自己雖然有印 `file:line`，但訊息冇咁明確同可 grep）＋ diff 巨大 ＋ 改壞風險高 |

### 建議

**最推薦 C（收窄成「只守 `set +e` 窗口內嘅裸斷言」）**，理由：

1. **理據誠實**：守住嘅係 repo **實際存在**（3 處）嘅真·會假綠場景，而唔係一條已被推翻嘅前提。
2. **成本低於想像**：`set +e` 窗口只喺 3 處 → 大部分 corpus 唔受影響，唔會產生新假紅。
3. **釋放 236 條改寫**（可選、逐步）——令「fail-fast 慣例」由**硬規則**變回**慣例**，
   減少未來新探針嘅寫法負擔。
4. **唔需要**動 `9c04aaa` 嘅改寫 → diff 細、風險低。

**次選 A（保留現狀）** —— 前提已更正，規則無害，現行 violations = 0，**唔急**。
若果只想做最低風險嘅嘢，揀 A 就夠。

**明確唔建議 D**：拎走診斷訊息換取 diff 細，係倒退回。
